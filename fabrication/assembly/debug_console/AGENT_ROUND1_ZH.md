# 第一轮自主运行设计

按 [AGENT_CONTROL_ZH.md](AGENT_CONTROL_ZH.md) 执行。目标是让助手不靠人盯，自己跑完一轮：确认相机对应、查明“顶止挡后退不出来”的原因、补测剩余限位、录参考姿态。全程约 25 分钟，不动底盘。

## 目标

1. 确认三路机器人相机分别是头部、左腕还是右腕，并找出头部相机分别看左右臂时的指向值。
2. 查明顶到止挡后第一次退离为什么卡住，据此改进退离策略，去掉固定的 2.5 秒等待。
3. 补测：左右肘的上端（目前都是“在手动范围内受阻”，从竖直起点重测，看是真止挡还是姿态干涉）；右肩水平（113°，偏窄）和左肩水平（174°），两者都要先收起再测。头部水平、腕旋转和两端都已顶到止挡的项不再测。
4. 录参考姿态：收起、竖直、前伸（上臂前倾 45°、肘中位），每个姿态都配图和遥测。

## 用户回来后需要做的

- 机器人上电，笔记本开机，工作端打开移动热点。服务会自动启动，不用登录笔记本。
- 笔记本摄像头最好放在车的侧面（能看前后倾斜），离手臂 0.6 米以外。
- 车周围 0.6 米内不要有人或易碎物。
- 手柄可以关机；如果开着，放下别碰，任何输入都会让助手停止。

## 阶段 0：软件准备（不需要设备，第一轮开始前完成）

在 `debug_console` 新增 `agent_ops.py`，并在控制服务上开放以下接口（Studio 不转发，只给工作端经 SSH 在本机调用）：

| 接口 | 作用 | 安全约束 |
|---|---|---|
| `POST /api/agent/run` | 提交一个步骤序列，后台执行 | 与自检共用 running 标志，互斥；手柄输入或停止接口即中止 |
| 步骤 `move` | 多个关节同时移到目标值 | 只在当前限位内；全扭矩；受阻时等待重试（复用 `_move_retry`） |
| 步骤 `probe` | 调用现有限位自检项 | 规则同自检 |
| 步骤 `snapshot` | 抓机器人相机 0/1/2 和笔记本相机的单帧 | 正在推流的相机改从服务内的流取帧 |
| 步骤 `sample` | 按指定频率记录某些关节的遥测和寄存器（42/48/56/60/65/66/69） | 只读 |
| 步骤 `wait` | 等待，期间可中止 | — |
| `POST /api/agent/stop` | 立即停止，所有关节保持当前位置 | — |
| `GET /api/agent/status` | 当前步骤、实时遥测、已完成步骤和文件路径 | 只读 |

每次运行在 `evidence/<日期>/agent-runs/<run-id>/` 写入计划、逐步日志和图片。先用假总线测试：移动、受阻重试、中止、和自检互斥、相机不可用时的报错。测完按部署脚本发布。

## 阶段 1：上电预检（只读，约 2 分钟）

服务版本和开机任务状态；两块板的 USB 身份；16 颗电机的电压、温度和扭矩；没有接管、录制和采集；四路相机都出帧；拍基准图。任何一项不满足，就停下来报告，不进入下一阶段。

## 阶段 2：相机对应（头部和手腕小幅动作，约 3 分钟）

1. 三路机器人相机各抓一张基准图。
2. 头部水平先转 +10°，再转 −10°，然后回位，每次都抓图。整幅画面平移的那一路就是头部相机。
3. 左腕旋转先转 +20°，再转 −20°，然后回位，每次都抓图。画面旋转的那一路是左腕相机；右腕照做。
4. 把对应关系存到 `.local-deploy/camera-roles.json`，并记入 PROJECT_STATE。
5. 头部俯仰向下、水平分别转向左右两侧，直到画面里能看到对应手臂的夹爪，记下这两组指向值，供后面拍照使用。

## 阶段 3：退离卡住实验（约 5 分钟，用左腕俯仰）

选左腕俯仰，因为它两端都有确认过的止挡（954 / 3282），也几乎不受重力影响。每个实验都先探到下端止挡，再按以下方式退离，同时以 50 Hz 记录位置、目标、负载、电流（69）、状态（65）和运动标志（66）：

- A：顶到后立刻退，测从发出退离目标到开始移动的延迟。
- B：顶到后分别等 0.5、1、2 秒再退。
- C：先把目标设到止挡内侧 5 个计数，等负载降下来，再退。
- D：把扭矩上限降到 0 约 0.2 秒再恢复，然后退。只在腕俯仰和夹爪上做，没有掉落风险。

按延迟最短、最稳定的方式改写退离逻辑，并补假总线测试。结论记入规范第 5 节。

## 阶段 4：补测限位（约 8 分钟）

依次测：左肘、右肘（从竖直起点，看上端是不是真止挡）；左臂收起后测左肩水平，右臂收起后测右肩水平。每项前后，头部相机都转向该手臂拍照，笔记本相机同时拍一张。图像里出现异常接触，或负载突然升高，就停止该项，并保留图片。

## 阶段 5：参考姿态与收尾（约 3 分钟）

两臂依次摆到竖直、前伸、收起，每个姿态停 2 秒，记录遥测和四路图像，存为参考姿态。最后两臂收起，16 颗电机保持扭矩，生成运行报告（每项的目标、动作、图片、数值、判断和把握程度、遗留问题），追加到 PROJECT_STATE，并提交推送。

## 停止和恢复

触发任一停止条件后，所有关节保持当前位置。助手先读负载、拍照，判断能否安全收起：能就收起，不能就保持现状并报告用户。单项失败继续做下一项；同一关节连续两次失败，跳过该臂剩下的项。

## 交付给用户

- 一份运行报告，包含每项的图片和数值。
- 相机对应表。
- 更新后的限位和参考姿态。
- 退离策略的改进和测试结果。
- 仍需用户决定的事项，例如是否放宽某个仍在手动范围内受阻的端点。
