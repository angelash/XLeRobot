# XLeRobot 本机调试与控制映射台 v2.1

地址：http://127.0.0.1:8765 。启动 `start.ps1`，停止 `stop.ps1`。

本版将串口监控、扭矩与原生手柄处理集中在 `control_runtime.py`，不再启动 `first_motion_controller.py` 子进程。两块板身份按USB序列号核对，不在多个程序之间争抢COM口。

## 操作

1. 打开手柄，确认 Gamepad 的“原生输入”在线。蓝牙已配对记录不代表当前已连接。
2. 勾选小范围测试与线路确认，点击“启动受限控制”。该动作不会移动机械臂，必须先松开LB再启动。
3. 按住LB，十字键左右选择可用关节，上下每次按下一步。默认右肩水平；每次16计数约1.4°，速度100计数/秒。
4. 松开LB会停止本次动作，保留扭矩支撑及接管；B也只停止本次动作，需松开再按LB继续。只有View或页面“结束接管”主动结束会话。手柄断开、输入500ms未更新、页面3秒无心跳、通信及编码器异常均暂停动作并保留接管；松开LB、B和方向键后，手动点击“恢复动作”，不会自动续发旧目标。关闭扭矩是独立操作，需先托住手臂。
5. 手柄图可点击查看每个按键的用途、对象、条件和结果，图上点击不发移动。A定位关节说明，Y切换简明/完整模式，Menu打开完整映射；其余未绑定键、摇杆和扳机只显示输入。底盘当前不参与动作。

网页状态、控制器处理和日志使用同一原生XInput输入，不需要浏览器Gamepad API唤醒，也不把“手柄在设备管理器存在”当作在线。

## 限位与设置

- 从16个电机读取Min/Max Position、Homing Offset和当前位置到本机 `fabrication/assembly/device-calibration.json`，不写硬件限位或零点。
- 这份文件是设备寄存器快照，不是完整机械限位的人工验证；此前根据旧位置随意生成的±512文件不再被本版使用。
- 每次接管还限制在起点±96计数约8.4°与原有限位的交集中；单步4–32计数，速度40–150计数/秒。网页显示设备与本轮范围、正反向余量；触限只提示并保留接管，可反向或换关节。靠近边界时缩短本步并明确提示；不扩大限位。
- 保存行程不足24计数、或当前位置明显不在设备范围内的关节显示“限位待校准”。不可通过猜测扩大硬件限位；后续人工支撑手臂按真实行程重新校准。
- 扭矩开关只写保持目标与扭矩，不再修改PID、模式或清零所有位置模式的速度。位置动作会显式写有限非零速度，便于限制速度。实机对照已确认速度0也能移动；原先左肩目标超出仅7计数的保存限位才是该次不动的直接原因。

## 排障日志

页面底部按时间显示 input（按键原始状态）、axes（摇杆/扳机）、lb、select、blocked、command、feedback、no_motion、error 和启停事件。command只是目标已发送，feedback才表示实测编码器变化；无变化会暂停动作并保留接管。短按通过原生事件捕获，即使在两次网页轮询间按下又松开也显示“刚按过”；日志原始字段展开后不会被刷新收起。

日志在 `fabrication/assembly/evidence/<本地日期>/control-events.jsonl`，页面“导出诊断日志”可下载。本机设备快照、运行日志和测试轨迹不提交Git。
