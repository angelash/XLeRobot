# XLeRobot 只读可视化调试台

本工具用于当前装配阶段的硬件观测：串口监控只发送 Feetech PING 和 READ。页面另有“受限控制”启停入口，实际动作由独立 `first_motion_controller.py` 执行；Web 本身不发送关节目标。

打开后先看“操作许可”：观测、校准、受限动作三种许可。红色逻辑块表示条件不足；`阻断`行会写明还缺哪块板、几个电机、相机、手柄、校准或安全确认。硬件在线不等于可动作，必须全部条件满足。

“实时操作”显示独立控制器的在线状态、扭矩是否实际开启、当前关节和最近动作。控制器每秒上报心跳；状态超过3秒没有更新会显示 `STALE`，防止程序异常后仍显示旧状态。

动作前先勾选两个人工确认：车轮离地且线路安全、左右臂和关节方向已实物核对。勾选只能解锁许可判断，不能替代硬件与校准检查。

## 扭矩保持

“打开全部扭矩”和“打开这个”只执行保持，不发送相对移动：先读取每个舵机当前位置，暂时关闭扭矩，切到位置模式，写入当前位置为目标、目标速度 0，再打开扭矩。若任一目标电机未扫描到，整次请求拒绝。关闭操作写目标速度 0 并关闭扭矩。

Web 不能通过此功能移动关节或轮子。动作仍只能由独立受限控制器执行；使用动作控制器前先停止 Web 扭矩相关操作并让出串口。每次请求回读实际扭矩、目标位置和当前位置；回读不一致会显示在结果中。

## 启动

```powershell
cd F:\workspace\github\XLeRobot
.\\.venv-debug\Scripts\python.exe -m uvicorn fabrication.assembly.debug_console.app:app --host 127.0.0.1 --port 8765
```

浏览器打开 http://127.0.0.1:8765 。

也可运行 `.\fabrication\assembly\debug_console\start.ps1 -OpenBrowser` 后台启动并打开页面；运行 `stop.ps1` 结束。运行机器人控制程序前必须先停止调试台，让出串口。

页面包含操作许可、阻断原因、控制器/扭矩/当前关节/最近动作，以及三路 UVC、COM3/COM4、STS3215 型号/扭矩/位置/电压/温度和手柄输入。手柄区块只做浏览器显示；实际输入由独立 pygame 控制器读取。

操作许可需要同时满足：两块板在线、16 个电机应答、三路相机、手柄连接、本机校准完成，以及用户勾选离地和关节映射确认。受限控制启动后，控制器先保持扭矩 OFF；按住 LB 才使能，松开立即停止。

控制器每秒写一次心跳。页面超过 3 秒未收到心跳会显示 `STALE`，不会把失联后的历史状态误认成在线；启动按钮仍受硬件、校准、手柄和安全确认约束。

注意：设备枚举成功不等于“动作通路已安全可用”。相机顺序与物理左腕、右腕、头部对应关系仍需逐台遮镜头确认。

依赖：`.venv-debug` 复用系统 FastAPI/uvicorn/OpenCV，并单独安装 pyserial/pygame。相机流调用本机 FFmpeg DirectShow。

## 手柄控制边界

仓库已有官方 Xbox 示例 `software/examples/5_xlerobot_teleop_xbox.py`，但导入的是 0.3/三全向轮 `XLerobot`，不能直接套到当前 0.4 双轮 `XLerobot2Wheels`。当前界面只做手柄输入可视化；真正控制需在 COM4、12V 供电、停车逻辑与双轮 ID 映射通过后，单独适配双轮 teleop。
