# PICO Neo3 VR 遥控需求分析

2026-11-26，按用户要求整理：用户已有 PICO Neo3，希望用它控制 XLeRobot——左摇杆移动底盘，右摇杆转镜头，机械臂跟随手柄的空间运动（夹爪尽量贴合手柄位置），带重置校准，扳机控制抓取；其余细节由助手补全并落地，准备安装包。

使用说明见 [PICO_VR_ZH.md](PICO_VR_ZH.md)。本文记录需求、取舍和验收标准。

2026-11-27用户体验补充：用户已经在头显中进入预演，要求正视／侧视／俯视同时核对、屏幕可上下调整，并能在VR内进入实机。实现三视图共用同一骨架、Y按视线摆屏与Y＋右摇杆平移，以及X+A两段安全确认；调屏／切换后需输入回中。实际折叠臂姿超出现有单分支IK，保留拒绝并提供低速左臂逐关节准备，不通过放宽逆解或自动展开绕过。右臂故障hold和底盘停止锁保留，只开放未受限功能。头显页面读回、假总线测试、用户实际运动分别验收，不把前两者当实物跟随完成。

该补充已在车载部署：135项车载回归通过，实际PICO浏览器读到新版三视图、高度控制、受限说明并报告immersive-vr支持；无线ADB的HTTPS脚本SHA与部署源码一致。原16电机卸力／停车与三路新帧通过，没有开启真实接管或运动；双臂跟随、底盘行驶和抓放整体验收仍受原故障处理与物理验证约束。

2026-11-27进度：已完成车载代码安装、Monitor维护重启、121项车载回归、实际HTTPS与三路相机新帧检查，并放行PICO的热点地址。下文11-26车况为立项时的约束记录，后续以PROJECT_STATE.md最新交接为准；头显安装、WebXR和物理操作仍待验收。

## 1 用户目标与验收

**目标**：戴上 PICO，看着机器人相机画面，用双手直接操作整台车：走、看、伸手、抓、放。

**整体验收**（全部在真车上完成才算交付，软件测试不能代替）：

1. PICO 浏览器打开车载 Studio 的 VR 页，进入沉浸模式后能看到头部和两个腕部相机画面。
2. 左摇杆前推车前进、左右转向；松开立即停车。
3. 右摇杆转头部（水平／俯仰）；松开停在原位。
4. 按住握把（侧键）时，同侧机械臂跟随手柄移动；手前移 10 cm，夹爪大致前移 10 cm（比例可调）；手腕上下翻、左右转，夹爪俯仰和旋转跟着动。松开握把手臂停住。
5. 扳机按深浅控制夹爪开合；夹到物体后保持轻夹，松开扳机张开。
6. 校准／重置：任何时候都能重新对齐“手柄 ↔ 夹爪”，不会因为重新对齐让手臂突然跳动。
7. 摘下头显、网络中断、页面切走或按急停键，机器人在 650 ms 租约内停止，且不会自动恢复旧输入。

## 2 现状与约束（来自仓库和规范）

| 项目 | 现状 | 对方案的影响 |
|---|---|---|
| 统一平台 | 所有机器人能力必须进 8770 Studio（`robot-platform.mdc`） | VR 页挂在 Studio 的 `/vr/`，导航新增“VR遥控”；不另开端口或站点 |
| 唯一串口所有者 | 8765 控制服务；网页遥控走 `/api/web/*` 租约会话 | VR 复用同一网页会话（随机令牌、递增序号、650 ms 租约、手柄抢占、互斥），新增 `vr-input` 输入通道 |
| 机械臂运动学 | 二连杆平面 IK（肩抬升、肘），腕俯仰按“三关节和”保持；需要已核验的 2/3/4 关节参考和夹爪开合端点 | VR 末端跟随沿用这套参考；缺参考时该臂不开放 |
| 肩水平、腕旋转 | 标定只存“当时位置”作原点，没有绝对零位 | 只能做相对控制：接合时记录当前角度，按手柄相对变化转动；方向沿用“逐轴设置” |
| 速度上限 | 逐轴设置默认 12°/s、夹爪 120 raw/s；网页键盘另限 12°/s、100 raw/s | VR 以逐轴设置为上限（另有 45°/s 封顶），不擅自提高；默认偏慢，用户可在控制设置里调高 |
| 总线吞吐 | 11-24 实测状态读取约 200–330 ms／次；每颗舵机每次命令要读写多次 | VR 只给目标有变化的关节发命令；实际跟手刷新率要上车实测 |
| 安全规范 | 受阻即停；夹爪夹到物体保持轻夹；温度、电压、模式、扭矩异常停止；手柄输入优先 | 全部继承。夹爪在 VR 下受阻改为轻夹保持（与原版手柄一致），其余关节受阻仍结束会话 |
| 网络 | 工作端热点 192.168.137.x，笔记本固定 .150；8770 防火墙只放行登记的客户端 | PICO 连同一热点；需把 PICO 的地址加入放行名单和允许来源 |
| WebXR | 浏览器只在安全上下文（HTTPS 或 localhost）开放 WebXR | 8770 增加可选 HTTPS：同一端口自动识别 TLS 与明文，原有 HTTP 用户不受影响 |
| 当前车况 | 2026-11-24 用户要求休眠；`uncommanded_pose_change` 锁与右肩 hold 保留 | 本次只在工作端开发、测试和打包；不唤醒笔记本、不部署、不动车。上车同步与实测待用户下次授权 |

## 3 方案选择

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. Studio 内 WebXR 页（采用）** | 不装原生 VR 程序；与 Studio 同一入口、同一控制链；复用浏览器 WebXR | 需要 HTTPS；PICO 浏览器版本的 WebXR、按键编号与证书行为要真机核对 | 采用 |
| B. 上游 XLeVR（独立 HTTPS+WebSocket 端口、直连 LeRobot 驱动） | 上游现成 | 另开端口和硬件拥有者，违背统一平台与唯一串口规则；只在 Quest 3 验证过 | 不采用，只参考 |
| C. 原生 OpenXR APK（Unity/Godot） | 延迟最低、无证书问题 | 工具链重，需要另写一套控制与视频链路 | 暂不做，留作后续 |

安装包因此分两部分：**PICO 端启动器 APK**（填写机器人地址、连通测试、下载证书、一键用 PICO 浏览器打开 VR 页）和**车载端更新包**（新代码、HTTPS 证书、网络配置脚本）。

## 4 功能需求

### 4.1 输入映射（默认）

| 输入 | 功能 | 说明 |
|---|---|---|
| 左摇杆 前／后 | 底盘前进／后退 | 死区 15%，按 25% 分档，档位稳定以便原有“轮子未按方向转”保护生效；上限沿用网页 160 raw |
| 左摇杆 左／右 | 底盘左转／右转 | 同上；可与前后同时 |
| 右摇杆 左／右 | 头部水平转动 | 速率控制，速度与摇杆幅度成比例 |
| 右摇杆 前／后 | 头部抬头／低头 | 前推抬头 |
| 左／右 握把（按住） | 同侧机械臂接合跟随 | 物理左臂 = 左手；按下瞬间记录手柄和手臂当前位置（自动重置对齐），松开即停 |
| 左／右 扳机 | 同侧夹爪开合 | 按深浅比例控制；会话开启后第一次按扳机才接管夹爪，避免开启时夹爪突然张开 |
| X／A（短按） | 重新校准“正前方” | 以当前头显朝向为身体正前方；握把按住时无效 |
| B | 急停 | 立即结束控制会话，所有关节保持、底盘归零 |
| Y | 画面重新摆放 | 相机画面移到当前视线正前方 |
| 左摇杆按下 | 底盘快／慢档切换 | 慢档 50% |
| 右摇杆按下 | 手臂精细模式 | 位移比例减半 |
| X + A 同时长按 1.5 s | 开启／重新开启控制 | 需进入 VR 前已勾选安全确认 |

### 4.2 机械臂跟随（核心）

- **接合即对齐**：按住握把的瞬间，服务端读取该臂各关节当前编码器，算出腕部在“二连杆平面”的位置和当前腕俯仰总角、肩水平和腕旋转原始值；客户端同时记录手柄位置和姿态。之后每帧只发送“相对接合时刻的变化量”，服务端按 `当前目标 = 接合姿态 + 比例 × 手柄变化` 计算，丢包不累积误差。
- **重置校准**：松开握把→移动手到舒服位置→再按住，就重新对齐（离合式）。手柄与夹爪之间不存在会让手臂跳动的“绝对对齐”，因此任何时候重置都安全。
- **正前方**：手柄位移先转到“身体坐标系”（以校准时头显水平朝向为正前方），再映射到机器人：身体前后→沿手臂当前朝向伸缩，身体左右→肩水平转动，上下→高度。
- **位置**：径向距离与高度经二连杆逆解得到肩抬升和肘；左右位移换算成肩水平转角（考虑肩水平轴到抬升轴约 3 cm 前置量，来自 URDF）。
- **姿态**：手柄抬头／低头改变腕俯仰总角（夹爪随之抬低）；手柄绕自身前轴转动改变腕旋转。腕部跟随可在页面关闭（只跟位置，保持当前夹爪朝向）。
- **工作空间与限位**：目标超出二连杆工作空间或关节当前限位时，手臂停在最后可达位置并提示，手退回后继续跟随；不硬顶、不换逆解分支。接合时姿态已在模型外（例如完全折叠）则拒绝接合并提示先用键盘或手柄调整。
- **限速**：每个关节的指令目标以“逐轴设置速度 × 页面速度比例”逐帧逼近期望目标，且不超过当前位置 ±(跟随容差 − 8) 计数，避免触发“目标跟随滞后”。
- **异常值**：单次变化超过 0.6 m 或 180° 视为追踪跳变，丢弃；手柄失去追踪即视为松开握把。

### 4.3 夹爪

- 扳机 0 = 张开端，1 = 闭合端，线性插值；使用已核验的开合端点。
- 夹到物体（编码器受阻）时保持轻夹（最多 40 计数预压），不结束会话；扳机继续加深不再加压，松到受阻点外侧后恢复正常跟随。

### 4.4 VR 内显示

- 头部相机大画面居中，左腕／右腕画面在左下、右下（左腕画面在左边）。
- 状态面板：会话状态、各臂“空闲／跟随中／到边界／不可用及原因”、底盘档位、速度比例、最近一次服务端回执延迟、相机帧龄。
- 双手手柄显示为彩色小方块，接合中变亮。
- 按键诊断：状态面板显示当前按下的按键编号，用于核对 PICO 按键映射。

### 4.5 预演模式

不开启实机控制，手柄驱动 VR 内一个简化双臂模型，用同样的映射计算，用于熟悉操作和在没有机器人时验证 PICO 输入。机器人在线时也可先预演再开启实机。

### 4.6 HTTPS（同端口）

- 8770 可选开启 TLS：监听同一端口，首字节为 TLS 握手则走 HTTPS，否则走原 HTTP；`studio-network.json` 未配置 `tls` 时启动方式与现在完全一致。
- 证书：本地生成“XLeRobot 本地根证书 + 服务器证书”（含 192.168.137.150、127.0.0.1、localhost）。私钥只存车载 `.local-deploy/`，不入库、不打包到 PICO。根证书公开部分可在 `/vr/ca.crt` 下载，装进 PICO 后浏览器不再告警；不装也可以在浏览器里点“继续访问”。
- 允许来源加入 `https://192.168.137.150:8770`；防火墙放行名单加入 PICO 的地址。

## 5 非功能需求

- **安全优先**：所有动作经 8765 原有门控；不修改 ID、模式、PID、零点或固件；不扩大限位；不提高逐轴速度上限；不新增串口拥有者。
- **死人开关**：输入 20 Hz 左右发送，650 ms 未续租即停；退出 VR、页面隐藏、关闭标签都请求停止。
- **互斥**：与手柄接管、助手运行、自检、摆位、抓取任务、录制互斥；实体手柄任意输入结束 VR 会话。
- **可追溯**：开启、停止、受阻、轻夹都写入原控制事件日志；VR 输入经 Studio 记入空间连续记录时只保存底盘和接合状态摘要，不保存头显画面。
- **离线可用**：VR 页不依赖外网 CDN，所有脚本由 Studio 提供。
- **不影响现有功能**：键盘遥控行为不变；未开启 HTTPS 时 8770 行为不变。

## 6 风险与待确认

| 风险 | 处理 |
|---|---|
| PICO 浏览器按键编号与 WebXR 标准映射不一致（上游 XLeVR 用了不同编号） | 状态面板显示按键编号；页面提供“上游编号”兼容选项；首次上手先在预演模式核对 |
| 总线吞吐限制跟手刷新率（预计 5–10 Hz 量级） | 只发有变化的关节；上车实测后再决定是否需要同步读写优化（需另行评审） |
| 默认 12°/s 跟手偏慢 | 文档说明；由用户在控制设置中调高并在小范围验证 |
| 肩水平、腕旋转方向依赖逐轴设置 | 首次使用小幅核对；方向不对在控制设置翻转 |
| 自签证书在 PICO 浏览器的行为 | 两条路：点“继续访问”或安装本地根证书；不行时备选 USB/无线 adb 反向端口（localhost 本身就是安全上下文） |
| PICO 在热点上的地址可能变化 | 网络配置脚本可重复运行；文档说明 |
| 车况：两项 hold 保留、休眠中 | 部署和实测需用户恢复授权；按开机清单先核验再同步 |

## 7 验证计划

1. **工作端离线**：服务端映射与安全的单元测试（假总线）；HTTPS 同端口识别测试；页面映射数学的 Node 测试；现有网页遥控、平台测试回归。
2. **工作端真机预览**：工作端临时以 HTTPS 启动 Studio（无 8765），PICO 打开 VR 页，在预演模式核对按键、位姿方向、画面布局。不涉及机器人。
3. **上车（待授权）**：按开机清单核验 16 电机与停车 → 同步代码并跑车载回归 → 只读核对 VR 页与 HTTPS → 架空或空旷处先只开头部和夹爪 → 单臂小范围跟随 → 双臂 → 底盘短距 → 抓放一次。每步记录到 PROJECT_STATE.md，新经验进 `AGENT_LEARNING_ZH.md`。
