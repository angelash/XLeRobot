## 2 v1实测暴露的问题（来自L-040–L-045）

| 现象 | 根因 | v2要求 |

| 第二步即被控制服务拒绝（L-043） | 仿真没有复刻单步900计数 | 仿真执行器复刻控制服务全部单步检查（已实现）；新增底盘步骤同样复刻 |
| 定距行走被挡住时要顶到6秒超时才停 | 只检查起步是否有进展 | 行进中0.35秒内双轮进展不足即判碰撞停车 |
| 每次都要大模型框选目标 | 没有把框选结果沉淀下来 | 成功后保存目标外观与参数，下次本地检出；按一致率晋级 |
| 配置保存全部参数，新默认值失效（L-045） | 持久化格式 | 只保存改动项（已实现） |

## 3 安全模型v2：允许碰撞，碰到即停

- **手臂**：所有靠近物体的动作用显式扭矩上限（推进45%、放下45%）和受阻即停；受阻后保持原位并后退，不重复顶推。整段移动按≤800计数切分，每段之间检查停止请求、手柄、温度和电压。
- **底盘**：只接受后退；每段0.5–5cm，按轮子计数停车；行进中双轮0.35秒内合计进展不足6计数即判“疑似碰撞”立即停车并报告；两轮不对称、反向或超量也停车。累计后退额度按授权文本计，额度20cm，在控制服务端持久记录，超额拒绝。
- **人员**：任何画面里有人进入手臂或车体运动范围就停止；后方没有相机，后退依据是用户授权和卡住即停，不能当作已看清后方。
- **失联**：抓取端4秒没有请求时控制服务结束会话并保持姿态；Studio或网络崩溃不会留下持续的轮速指令（每段有独立计时停车）。

## 4 能力需求

| 编号 | 能力 | 要求 | 验收 |
|---|---|---|---|
| R1 | 周围判断 | 头部相机左右扫视，左右腕相机看近处；结合用户授权判断能否后退；记录照片 | 有一组扫视照片和结论写入运行记录 |
| R2 | 底盘让位 | `/reposition`：按指定厘米后退，每段≤5cm，段间看腕部画面；卡住即停；记录轮计数估计与画面位移 | 后退10–20cm无异常停车；人为挡住时0.5秒内停 |
| R3 | 目标可见 | 观察位9cm、从后上方进入；看不到目标时先用头部画面判断位置，再让位或换观察点 | 碰倒事故不再发生（物体立在指尖前任何位置） |
| R4 | 抓起 | v1快速抓取；同时适用直立和侧躺的小物；夹住后核对 | 插头抓起并保持≥1.5秒 |
| R5 | 搬运 | 抓起后横移（肩水平，±8cm）或前后移再放下；放下后核对已留在新位置 | 放在横移4cm以上处并直立/平稳 |
| R6 | 大模型→本地 | 新情况先由大模型（助手看图）框选与决策（L0）；成功后保存目标模板，下一次由本地模板检出自动框选（L2），同时记录与大模型框的一致率 | 本地检出完成至少一次完整抓放；一致率进入台账 |
| R7 | 知识内化 | `platform-data/grasp/knowledge.json`：物体（模板、尺寸像素、成功参数）、场地（桌面高度、推进离桌）、底盘（每段计数→画面位移）、失败签名；启动时加载，页面可查看 | 新会话重启后仍能本地检出同一物体 |
| R8 | 记录与评估 | 每次运行记录用时、步数、大模型参与次数、是否本地检出、结果；可导入学习台账 | 结果文件含这些字段 |

## 5 大模型与本地模型的分工

- **L0 大模型主导**：新物体、新场地、异常（倒下、看不到、失败）时，由助手查看头部/腕部照片，决定让位距离、框选目标、调整离桌高度；动作仍通过有界步骤执行。
- **L2 本地接班**：成功抓起后，本地保存选择时的腕部模板（灰度）、目标尺寸和成功参数；之后在观察位用多尺度模板匹配检出（笔记本CPU约10ms/帧级），得分≥0.6才自动框选，否则交回大模型。每次同时有大模型框时记录交并比，按LEARNING_PROTOCOLS第5节：一致率≥95%且无危险漏检才改为本地优先、大模型抽检。
- **L3 技能参数**：成功一次的推进离桌、插入深度、加压量写入物体条目；下一次同一物体优先使用。

## 7 今天的验收顺序

1. 扫视周围并记录（R1）。
2. 夹爪在观察位、后退5cm×2–3段，看侧躺插头进入腕部画面（R2）。
3. 大模型框选侧躺插头，完整抓起，横移放置（R4、R5，L0）。
4. 保存知识；清除选择后，本地检出自动框选，再完成一次抓放（R6、R7，L2）。
5. 记录用时、步数、大模型参与次数与一致率（R8），提交推送并部署。
