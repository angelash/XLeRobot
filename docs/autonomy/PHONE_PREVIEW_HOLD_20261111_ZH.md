# 手机低帧率预览保帧修复

日期：2026-11-11。用户反馈手机预览在低帧率下反复闪烁，明确要求不清除旧画面。

当前AR主摄在手机端每500ms发布一次，接收元信息标为约2fps；普通Wi-Fi彩色采集请求10fps。网页之前复用了数据新鲜度期限，超期就清除图片，因此新帧之间会出现空白。此次修复显示生命周期，保留现有AR采集模式与帧率设置。

遥控视频墙、全局手机预览及手机详情页统一为：首次取得图片后，在等待下一帧、HTTP409、短时断流或解码失败时保留上一帧；显示“等待更新／保留上一帧”和时间，不继续标为实时。新图片先完成解码，再替换已显示图片并释放旧URL。折叠、切换镜头、明确停止或离页仍清理图片。

显示保留不会刷新源时间／会话／序号，后端1秒新鲜度判定不变。保存和深度查询仍需新鲜数据，详情页对保留深度图的点击明确提示等待新数据；实时点云继续执行原期限，不用旧图补足运动或几何证据。

验证：40项相关接口／镜头／控制回归通过。真实浏览器模拟约0.45fps、HTTP409与约3秒断流，三个入口各55份采样均0空白、0隐藏属性变化，恢复后均换入新图，无脚本异常。7静态文件逐项SHA热更新，未重载服务；控制PID15560、Studio PID41980及手机配置SHA保持，本轮0运动命令。临时快照、生成图、浏览器截图与原始回执仅留两端忽略目录。

实际车载网页保持原AR主摄：100份约100ms间隔采样中，20次新图替换、60份使用保留画面；0空白、0隐藏变化、0脚本异常。该窗口不等同于长期稳定性或光学端到端延迟验收。
