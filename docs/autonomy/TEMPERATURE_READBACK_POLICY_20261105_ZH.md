# 温度跳变按当次复读处理

2026-11-05用户指示：温度度数跳变先理解成检测设备异常，只要有正常温度读数就认为正常，不应因此打断正常测试。这是运行策略的调整，尚未证实跳变来自传感器、串口帧或供电。

原实现会将整段行驶中已复读正常的温度跳变累计，超过3次仍停车；夜间退离段因此在约4.52cm中断。现在取消温度跳变的累计次数停车门，每次独立判断：同一电机初读异常时立即再读，初读加复读最多3份新包，只要出现正常值就使用该完整新包继续。例：92→52→35°C按检测读数异常记录并继续；3份持续异常则拒绝/停车。正常读数不增加采样开销，不使用其他电机、旧缓存、历史最低值或拼接温度替换整个状态包。

正常范围沿用各入口原门值：底盘短程/转向预检及计数行驶监控为1至小于45°C，实机准备和伺服关节遥测为1至小于50°C。0/无效读数、3份都未恢复、通信错误、状态故障仍进入拒绝/停车路径；原电压、扭矩、轮位反向/不对称、碰阻、租约、独立计时和人员边界继续生效。非温度故障原有复读/次数限制保留。新策略不自动重放已失败动作、不重置授权消费、不授予新移动范围；[本次夜间返回记录](NIGHT_EXPLORATION_20261105_ZH.md)和旧失败样本保持原判定。

实现为`temperature_guard.py`，在`rotation_scan.py`、`original_runtime.py`和`servo_session.py`共用；保留初读/复读原始包、`recovered`和阶段信息，关节遥测及准备回执也保留异常复核信息。既有8765的`/api/servo/status`返回`temperature_policy=same-motor-fresh-normal-v1`，8770仍使用同一控制服务。已按用户直接指示更新已审核规范的温度条款；L-101新增方法仍标待审核，不擅自合并旧经验。
