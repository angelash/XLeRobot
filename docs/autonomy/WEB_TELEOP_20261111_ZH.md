# Studio 网页遥控交付记录

日期：2026-11-11。需求为在现有网页用方向键驾驶机器人，并提供手臂与其他设备的简易联动、屏幕按钮和逐关节精调。

## 已交付

原车载入口 `http://192.168.137.150:8770/#teleop`，主导航“键盘遥控”，总览、控制中心及能力目录均有入口。使用同一Studio应用及原8765串口所有者。完整按键和操作方法见[使用说明](../../fabrication/assembly/debug_console/WEB_TELEOP_ZH.md)。

底盘用方向键和屏幕方向盘；双臂可选物理左侧、右侧或同时控制，联动模式提供末端伸缩／升降、肩转、腕姿和夹爪，精调模式提供6关节独立正负向按钮、选中关节的括号键和实测编码器。头部使用IJKL及对应按钮，相机区按需显示头部／左右腕快照。速度默认50%，Shift临时精细操作。

开启需主动确认，准备可用设备保持实际当前位置；无自动归零、限位扩大、模式／PID／零点修改。网页输入每100ms发送完整按键集合，650ms租约；令牌和序号隔离浏览器会话，状态轮询不续期。松键立即保持，失焦、后台、切页、断网或故障结束会话；实体手柄有效输入结束网页会话。保持失败与无停止回执有独立提示。租约不是硬实时停车承诺。

联动从真实位置与已验证参考计算；全部选中手臂通过整组预检才输出。参考不匹配、IK分支不适合当前折叠姿态或超出设备限位时停止，提示逐关节调整。开合方向来自夹爪端点，松键保持开度。沿用维护隔离与任务互斥，关节受阻结束网页会话，双轮有未转动／反向／位移比例异常检查。

## 验证与发布

- 工作端既有控制／平台相关回归134项通过，后续新增电压与双轮比例检查后，新控制20项通过；车载最终136项回归通过，另有1条非失败warning。使用假STS总线及生成输入，没有连接测试运行到真实电机。
- Node键位检查3项通过。真实Chromium内核浏览器9项交互通过：页面初次进入不发运动、方向键与松键、中性输入、逐关节选择、按钮拖出后松手、输入控件隔离、失焦停止、空格终止、390px无横向溢出及无页面脚本异常（部分行为归并在同一检查）。
- 发布15份源码，逐文件SHA读回。先备份，车载回归通过后按控制服务、Studio顺序独立重载。原有5份关键配置SHA保持，16颗电机扭矩状态保持，原启用安卓采集恢复。网页控制最终关闭。
- 首次发布因运行环境不含pytest而在服务重载前恢复旧源码；发现已有隔离test-tools后使用它运行检查。再次遇到并行首页SHA变化，保护拒绝发生在重载前；下载确认仅新增手机预览引用，合并保留后成功。原失败与回执均保留。
- 独立SSH复查发现直接启动的新服务随部署SSH会话结束退出；改由原有XLeRobot-Boot／Monitor任务恢复，不新增任务。随后另一SSH中3次读到不同时间戳的16电机，15源码SHA一致，三路UVC各返回真实JPEG；未确认启动及无效会话输入均被拒绝，私有servo路由仍关闭。原安卓启用状态在持久服务中再次恢复。
