# 历史轨迹、时间轴与可交互3D空间

日期：2026-11-06。入口：既有XLeRobot Studio `8770/#fieldmap`，内部视图`/fieldmap/view`。用户要求先分析和归档设计、提交推送，再开发；本文件为该开发基线，后续追加实际验收结果。

## 目标与现状

用户需要在原观察台选择时间范围，看到历史移动轨迹及可拖动的时间轴，选择当时拍摄的照片，并在真正的3D场景中旋转、缩放查看环境。还应能回答“这段实际走了什么、哪次失败、何时停下、该照片和位置是否同一时刻”，避免只呈现一条无法核对的线。

当前页面的立体按钮只是SVG斜投影。地图只有当前快照，旧图和复核虽有归档但未提供选择；历史动作在agent-runs和servo-sessions，逐步照片及真实捕获时间还散在FieldTests的ZIP中。车载只读盘点325伺服会话、226助手运行、278个顶层过程ZIP；数字仅为本次盘点，不等于全部都可重建轨迹。电机当前无响应，本次开发、导入、页面验收不依赖开电机，不发移动或关节动作。

## 使用流程

1. 打开“空间观察”，默认展示最近有记录的一段时间；可切换当前环境快照或历史轨迹。
2. 通过本地日期时间起止选择、最近一次/当天/全部快捷范围和运行筛选，查询该范围。跨午夜正常处理，显示明确时区；服务保存带时区时间，不混用文件名日期或进程启动日。
3. 时间轴显示移动、转向、观察、失败标记及游标。可点击跳转、拖动游标、滚轮缩放时间窗、拖拽平移时间窗、键盘逐事件、播放/暂停与倍速。暂停和拖动立即更新选中时刻，手动查询中止旧请求，迟到响应不能覆盖新选择。
4. 地图显示分段轨迹、起终点、选中时刻机器人位置/朝向和选中动作。重叠往返可通过时间轴、事件列表和逐步按钮区分；原始动作次数、累计路程、失败数单独呈现。
5. 照片栏按头部/左腕/右腕/其他分类选择，显示最近照片的实际时间、早于/晚于游标的时间差及时间来源；没有对应照片就显示缺失。可切换该时间范围内的照片列表，分页加载、查看原图、点击照片反向定位时间轴。三路照片不是同步曝光，不用旧帧冒充实时。
6. 选择环境快照时继续查看原有物品标注和复核；历史快照只读，当前地图保留原复核保存与冲突检查。历史回放和实时遥测分区，回放停止/播放不发送机器人动作。

## 完整性与坐标定义

- 从实际编码器差还原，保留请求距离与实际轮估的区别。失败事件能取得部分位移就显示部分轨迹，未执行的计划不算移动；读取失败或缺轮位则保留事件、断开轨迹。
- 同一连续坐标段以自身起点为(0,0)，x向初始前方、y向左、yaw按现有控制几何约定。轮半径/轮距优先使用记录值，否则明确采用资料值63.5mm/250mm；保留几何来源与方向标定状态。轨迹由双轮差分积分，含中途计数轨迹和转向；不把累计里程当离起点距离。
- 原始轮位会4096回绕，每条有限动作的实际delta优先；无delta时只在可确认不超过半圈的局部读数间使用回绕差。进程重启、较长空档、轮位不连续、方向约定不明或外部推车时分段，绝不跨未知区画实线。相邻段不强行拼成同一房间坐标。
- 轮估会漂移。照片视觉回位记录只作证据，不自动把轨迹端点吸到起点，不标“精确位置”。时间不足的动作以完成时刻和duration/elapsed回推，明确`time_basis`，其内插时刻也是估计。
- 现有环境对象是相对方位示意，不能把示意单位和轨迹米制直接叠成精确地图。因此环境视图与轮估轨迹视图切换显示，明确各自尺度；为将来加入经标定map-to-odometry变换预留字段，本期没有变换时不伪造对齐。
- 3D采用真实透视相机、深度测试、地面网格、可选物体/轨迹/机器人几何，物品高度仍标未测假设；这实现可交互立体浏览，不把RGB照片变成已重建的稠密点云。后续接入深度、相机内外参和SLAM可以替换几何来源。

## 后端与数据

新增`deployment/fieldmap/history.py`，SQLite索引存放在既有FieldMap私有数据目录下的`history/`，保留源文件不迁移、不删除。SQLite单独短连接、WAL和事务；相同源文件mtime/长度指纹未变即跳过，按稳定运行ID去重，同一动作的原目录和导出ZIP不能双计里程。完整重建为可恢复的缓存操作，不修改运行回执。

来源由部署配置固定为仓库evidence和本机FieldTests根目录，不接受网页传任意目录。支持：

- `agent-runs/<id>/result.json`及steps.jsonl、直接引用图片；含travel/rotate/advance/drive和失败rotation证据。
- `servo-sessions/<id>/session.json`、steps.jsonl、result.json；包括base_full、部分失败证据和停止回读。
- 成对过程照片ZIP与control ZIP：通过会话ID/旁边的run_id回执关联，使用log.json的captured_at或agent快照时间，保留缺失/估计时间标签。聚合备份ZIP和重复归档目录不作为另一轮运行。
- 已有地图`map.json`和history下地图快照。按地图ID列出，不能覆盖旧复核。

历史索引是Studio进程内低优先级后台任务，启动扫描一次、随后定期增量扫描，手动刷新立即返回任务状态，不阻塞HTTP事件循环。每次有文件/字节/事件预算，截断和损坏来源显示覆盖缺口，不能用空列表称“全部完成”；正在写入的JSON失败保留上次成功索引，下次重试。历史查询即使机器人服务离线也能工作。

接口统一挂`/api/platform/fieldmap/history/*`：状态/刷新、运行列表、范围轨迹和事件、照片分页及最近相机照片；图片按索引产生的不透明ID访问，缩略图懒生成并缓存。增加地图快照目录/读取接口，历史复核只读。返回数据含范围、分段ID、位姿来源、时间来源、计数、失败原因、照片链接、分页/截断字段和`motion_enabled=false`。后台查询最多返回限定事件和轨迹点，图像按视口需要加载；不把上千张原图或原始70字节寄存器塞给前端。

图片只允许索引真实引用的JPEG/PNG文件或ZIP成员。解析路径后必须留在固定来源根内；拒绝路径穿越、符号链接越界、聚合包/异常大成员和解压炸弹，按需读取不解压任意目录。缩略图先校验图片格式、像素数及字节上限；接口不暴露工作站密钥、原始授权文本或绝对本机路径。运行照片、索引、日志、缓存均不提交Git。

## 前端与3D

沿用现有深绿/浅米色观察台，主视图区保留“平面/3D/复位”，新增“环境/轨迹”数据模式和地图快照选择。轨迹模式下左地图、右照片，时间轴横贯下方，动作详情紧邻游标；窄屏按地图、时间轴、照片排列。屏幕阅读器可读取时刻、事件和相机，不仅靠颜色表达失败/未知。

Three.js复用仓库已锁定的0.180.0离线资源；增加同版本OrbitControls及完整性清单，不用外网CDN。左键/单指旋转、右键平移、滚轮/双指缩放、按钮复位，2D模式保留为无WebGL时的可用回退。对象使用有实际高度的Mesh，区域用地面形状，轨迹用分段线，选中时刻机器人有朝向；点击对象/轨迹联动详情。隐藏页停止绘制，限制像素比、按需渲染、释放geometry/material/listener，避免车载弱CPU/GPU持续空转。WebGL丢失显示状态并可回2D，轨迹不能因3D失败消失。

照片和查询带AbortController/递增请求编号；游标拖动本地位置即时更新，照片请求去抖并缓存，避免每个像素发请求。相机切换保留时刻。查询空范围、无轨迹但有照片、无照片但有动作、坏图/断网、分页末尾和时间窗边界都有可见状态。历史回放不自动滚回实时；刷新可保留选中范围和时刻。

## 开发与验收顺序

1. 本设计提交推送，随后实现索引/格式适配、受限查询和图片接口；用生成数据覆盖4096回绕、失败部分、重复源、跨午夜、缺失照片、损坏/活动文件、路径越界和分页。
2. 实现时间轴/照片/事件联动及真实3D，保留当前地图复核、停止按钮和统一平台入口；本地用独立fixture服务验证，无机器人连接或动作。
3. 浏览器实际拖动、平移/缩放时间轴、播放暂停、相机切换、照片反向跳时、3D旋转/缩放/平移、2D回退、窄屏和错误路径；检查浏览器控制台与网络，只允许只读查询及显式索引刷新。
4. 本机通过后备份运行文件和私有地图，部署笔记本，只在无活动动作/录制时重启8770；8765不重启。索引既有历史，核对最近夜间200平移/8转向、1656照片的去重/覆盖边界，不以文件扫描成功代替回放验收。
5. 笔记本回归、真实8770页面验证和索引/图片回读；记录导入数、失败/跳过源、性能、已知限制。追加PROJECT_STATE和待审核经验，代码/文档提交推送，完整源码与运行文件分别核对哈希。

本期完成标准：用户能在原页面选择任意有数据时间段、拖动并播放轨迹、查看对应相机照片、定位失败、旋转缩放真正3D场景；没有数据时明确显示缺口。当前数据能提供轮估回放及示意环境，不承诺度量SLAM、全周深度重建、无人导航或新的硬件运动验收。
