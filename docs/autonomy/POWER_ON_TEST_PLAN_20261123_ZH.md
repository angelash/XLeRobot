## 1. iPhone 前置摄像头够不够用

**现在能说的**：近处的事有希望够用，全屋范围的事单靠它不够；是否真的够用，取决于下面第 3 步的卷尺验收，这一步从来没做过。

依据：

| 事实 | 来源 |
|---|---|

| 11-09 在工作端经 USB 取到过 480×640、30 帧/秒的浮点米制深度，有内参，正值像素约 70–83% | 既有记录 |
| 11-10 上车后 iPhone 的 USB 反复掉线，原因没查清；当时提出改接笔记本机身 USB 口、绕开扩展坞，没有做 | 既有记录 |
| 之后一直用 Wi-Fi：深度被编码成色相视频，有损，240×320 或 180×240，量程上限约 2.8 m，0.2–3 m 有效像素约 59–64%，没有置信度和相机位姿 | 既有记录、源码 `deployment/phone_vision/iphone_wifi.py` |
| 手机深度**从未和卷尺对过**，精度和可用量程都是未知数 | 既有记录 |

| TrueDepth 是为人脸距离设计的结构光，一般认为一两米外会明显变差 | 通用认识，**未在本机验证** |

按用途的预期（都要等实测确认）：

| 用途 | 预期 | 取决于 |
|---|---|---|
| 桌面抓取测距（0.25–0.7 m） | 有希望 | P1 在该量程误差 ≤1 cm；手机到手臂的位置关系 |
| 近处障碍与前方净空（约 0.5–1.5 m） | 有希望 | P1 近障量程；手机视野够宽、能看到车前地面 |
| 轮径、轮距标定的外部真值（对着墙） | 有希望，且最划算 | P1 通过；P2 与卷尺对照一致 |
| 短距离位姿跟踪 | 可能 | 已有 RGB-D 转角估计，需真值对照 |
| 房间尺度建图、全屋定位、A 点到 B 点 | 单靠它不够 | 量程短、视野窄；需另加视觉标记或特征定位，仍可不采购 |

## 2. 已备好的工具

| 工具 | 作用 | 离线测试 |
|---|---|---|
| `deployment/phone_vision/depth_accuracy.py` | P1：按卷尺距离逐档采集，分用途给出通过/不通过、可读量程和线性修正建议；USB 原始深度与 Wi-Fi 色相深度分开评 | 8 项 |
| `deployment/phone_vision/depth_motion.py` `clearance` | 由地面求手机的离地高度、俯仰和横滚；给出车身通道内前方已确认空闲的距离。看不到的地面算未知，不算空闲；下沉台阶算障碍 | 13 项（与下一行合计） |

这些工具都只读数据、不发运动命令。门槛里只有抓取量程 1 cm 沿用已审核的 G1，近障（2 cm 或 3%）、房间（5%）和同步采样的各项限值是**待审建议值**。

## 3. 开机前请准备

1. iPhone 充好电，带数据线。优先把线**直接插笔记本机身的 USB 口**，不要经扩展坞；这样既能试 USB 原始深度，也能边测边充电。
2. 一把卷尺（3 m 以上）。
3. 一面平整、哑光、浅色的墙，墙前留出 3 m 空地。玻璃、镜面、深色反光面不要用。
4. 机器人放在这面墙前，车头（手机镜头）大致正对墙面，周围清空。
5. Record3D 打开，前置摄像头，按要测的通路选 USB 或 Wi-Fi 出流。

### 第 3 步 P1 卷尺验收（最关键）

你来做：把车（或手机）放到离墙指定距离，用卷尺量**镜头到墙面的垂直距离**，把读数告诉我。建议档位：30、50、70、100、140、200、300 cm。

我来做，每档一次：

```powershell
python -m deployment.phone_vision.depth_accuracy capture --truth-cm 50 --root D:\Robot\FieldTests\20261123\phone-depth-p1
```

全部档位完成后：

```powershell
python -m deployment.phone_vision.depth_accuracy report --root D:\Robot\FieldTests\20261123\phone-depth-p1
```

- 通过门槛：见第 2 节。报告按用途分别给结论，某个用途通过不代表其他用途通过。
- 报告里的线性修正只是建议，不会自动应用。
- 不通过时：该深度源不得用于对应用途，也不进入第 5 步。

### 第 4 步 手机位姿与前方净空（静止）

```powershell
python -m deployment.phone_vision.spatial_probe --output D:\Robot\FieldTests\20261123\phone-floor-01
```

```powershell

```

- 需要你提供或当场量：车身最宽处的宽度、手机相对车身中线的左右偏移。
- 看三件事：算出的离地高度与卷尺量的是否一致；前方多远之内看不到地面（盲区）；在车前放一个箱子，报告的障碍距离与卷尺是否一致。
- 盲区过大或看不到车身通道两侧的地面，说明手机需要调低俯角或换位置，这要你动手调整。

### 第 5 步 P2 方向核对与 W2/W3 标定（**需要你当场授权底盘受限运动**）

- 只用现有的受限短动作（每次几厘米、十几度），现有扭矩、限位、停车证据规则不变。
- 先做一次已知方向的小转和一次小前进，核对工具输出的左右、远近符号。
- 每次动作前后各取一组深度帧：

```powershell
python -m deployment.phone_vision.depth_motion change --before <动作前目录> --after <动作后目录>
```

- 前几次同时用卷尺量，两者一致后才单独用深度作真值。样本写入 W2、W3 会话，拟合轮径和轮距的候选模型。
- 候选模型是否采用由你决定；我不会改运行中的物理常数。
- 若 `uncommanded_pose_change` 锁阻止底盘动作，由你决定如何处理，我不自行清除。

## 5. 测完后的判定

| P1 结果 | 结论 |
|---|---|
| USB 原始深度在抓取和近障量程通过 | 不采购路线成立：抓取测距、近障净空、轮组标定都用它；继续做手机到车体的位置标定 |

| 两条通路在 1 m 内都不通过 | 手机深度只当参考画面，不作度量来源；轮组标定改用卷尺和地面标记，届时再谈是否采购 |

不论哪种结果，房间尺度的定位都需要另一套办法。不采购的选项是在墙上贴打印的视觉标记（仓库已有 A4 标记图）配合标定后的里程计，这部分还没有开始做。
