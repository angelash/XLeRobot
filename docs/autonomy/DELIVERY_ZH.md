# 自主学习与算力协同：首版交付与实测

日期：2026-11-02。按 [需求与设计](REQUIREMENTS_DESIGN_ZH.md) 开发并部署到车载笔记本。本轮没有驱动机器人、没有打开机器人相机或麦克风；实机实验按 [测试方案](ROBOT_TEST_PLAN_ZH.md) 明日进行。

## 使用方式

- **页面**：Studio左侧“自主学习”，或 `http://192.168.137.150:8770/#autonomy`。显示两端算力节点、能力与路由、近期计算任务、17项实验目录、学习会话、模型与标定审核、打印资产。页面只读取状态和提交计算任务，没有任何电机接口。
- **工作端节点**（在本机运行，主动连接笔记本，不开放入站端口）：
  1. 令牌由笔记本首次启动模块时生成在其私有平台数据 `autonomy/compute/worker-token.txt`；用现有SSH密钥复制到本机 `%LOCALAPPDATA%\XLeRobotRemote\autonomy-token.txt`，不要放进仓库。
  2. 运行 `deployment/autonomy/start-worker.ps1`（前台运行，Ctrl+C停止）；`-CpuSpeech` 强制语音走CPU，`-CudaDllDir <目录>` 指定cuDNN所在目录。
  3. 节点断开6秒后判离线；可回退的任务自动在笔记本执行。
- **计算接口**：`POST /api/platform/autonomy/jobs`，参数 `capability`、`payload`、`route`（auto/local/prefer_worker/worker_only）、`deadline_s`、`wait_s`。图片可直接引用车载助手运行的照片：`{"run_id":"20261103-101500","file":"00-x-cam1.jpg"}`，服务端按名称读取，不上传。
- **学习台账**：`/api/platform/autonomy/learning/*` 建会话、导入运行回执（只读复制轮组计数、关节读数、照片清单与失败信息）、补真值、标记离群、拟合、用其他会话验证；“采用”只能由用户在页面确认。标定结果可从已完成的计算任务直接保存。
- **打印资产**：页面“打印标定资产”或 `docs/autonomy/assets/`：9×6内角点25mm棋盘格、AprilTag 36h11 80mm（ID 0–3），均为A4横向300dpi，附100mm校验尺。

## 实测结果（2026-11-02 22:57–23:07）

部署：提交 `1f2be0a` 共26个文件，逐文件SHA核对；笔记本OpenCV 5.0环境43项回归通过；只重启Studio（PID 2832/4792→21492/7416），8765控制服务PID 10688不变。工作端节点经热点主动连接，注册13项能力。

| 项目 | 车载笔记本（i5-8265U，OpenCV 5.0） | 工作端（i9-13900HX，OpenCV 4.11） |
|---|---|---|
| JPEG解码640×480 | 2.1–2.8ms | 0.5ms |
| 棋盘格检测640×480 | 62–81ms | 25–27ms |
| AprilTag检测640×480 | 2.7–3.0ms | 0.6–0.7ms |
| SGBM视差640×480（96视差） | 68–81ms | 22–24ms |
| 12张图内参标定（256KB图像） | 792–872ms | 440–465ms（经网络总计454–500ms） |

- 两端标定结果一致：fx≈316.7、RMS≈0.117px，12张全部可用。
- 连通：工作端回显20次，服务端提交→结果中位62ms，工作端页面往返中位124ms、P90 126ms。
- 语音：SAPI合成的6.43秒中文句子，工作端CPU int8识别1.73–1.86秒（实时率约0.28），首次加载模型约1秒。默认把“小九”识别成“小酒”；加入 `hotwords`/`initial_prompt` 后得到“小九，请向前移动五厘米，然后停下来拍一张照片。”
- 安全/回退：错误令牌注册返回401；外部来源提交返回403；节点停止后6.7秒判离线，`prefer_worker`任务回退笔记本完成（约0.5秒），`worker_only`与识别任务立即明确失败。
- 笔记本资源：部署后可用内存约1.95–2.1GB/8GB，Studio新增模块常驻占用很小；计算线程固定1个，OpenCV内部线程限2。

## 算力分配结论（基于实测）

- **留在笔记本**：AprilTag检测（约3ms）、三角测量、地面单应换算、质量检查可按帧运行；棋盘格检测和SGBM约70–80ms，适合按需而不是持续高帧率；任何结果都在笔记本校验时效后才可能进入动作决策。
- **送到工作端**：单次计算超过约150ms、或批量标定/全分辨率视差/识别时更划算。当前网络开销约60ms加图像传输（256KB约数十毫秒），工作端CV约快3倍。
- **语音**：笔记本继续做唤醒、VAD和流式识别；工作端CPU复识别适合需要准确转写的较长指令（6秒句约1.8秒），短指令更快。GPU识别需要安装cuDNN 9（当前缺 `cudnn_ops64_9.dll`），装好后用 `-CudaDllDir` 启用。
- **本地模型**：工作端显存剩余约3.5GB，适合3–4B量化模型；需安装Ollama或llama.cpp并下载模型后，节点自动注册 `llm.chat`。云端大模型继续负责理解、规划和成败判断。

## 失败与修正（保留）

1. 首次部署时笔记本回归失败2项：运行目录没有设计文档，协议对照测试与平台源文件索引都依赖它们。部署脚本按设计在重启前中止并回滚；把设计文档作为新增文件一起发布后通过。
2. 首次语音任务让工作端节点整体崩溃：ctranslate2能看到CUDA，但缺cuDNN 9，原生加载直接终止进程。笔记本正确判定“执行中失联”，后续请求明确失败而不挂起。修正为子进程探测CUDA，失败自动用CPU int8。
3. 修正补丁首次把探测方法放到了类外，节点启动时识别能力被如实标为不可用；修正位置并补测试。
4. 节点把任务参数缺字段的KeyError误判为“不支持该能力”（会触发不必要的回退）；改为先判断能力是否存在，输入错误不回退。
5. 页面视觉验收：本机浏览器运行时返回“操作结果未知”，按其规则本轮停止浏览器操作；改用Node模拟DOM与接口数据验证渲染、转义与只读加载。真实页面观感待用户打开后确认。

## 限制与下一步

- 双目、手眼、地面单应、学习拟合只在合成数据上验证（含畸变相机：内参误差<1%，双目三角测量误差<4mm）；真实相机的标定、观测姿态重复性和测距精度明天按C1/A2/C3/G1实测。
- 模型“采用”只影响规划默认值，不会改写控制服务的轮径、限位或速度上限；接入控制前另行评审。
- 工作端节点目前由人工启动，不注册开机任务；需要常驻时再决定。
- 本地模型、GPU语音尚未安装；语音模块与 `speech.transcribe` 的接入由语音功能维护方按需启用。
