# 手机成像工作区与持续探索发布记录

日期：2026-11-11。此文件记录本轮软件发布和物理检查点；持续探索须依据实时状态，不能由此文档推定机器人正在移动。

用户要求原网页显示手机画面、灵活选择镜头、保存成像并呈现空间效果；同时沿可走通路持续寻路建图，直到用户停止。保留原8770 Studio与8765唯一串口所有者，没有新增用户站点、串口控制进程或开机任务。

## 使用入口与呈现

- 原导航“手机视觉” `/#phones`：当前启用设备优先；未启用iPhone折叠空白预览。红米主摄0、超广角2、前置1、近摄3可按需轮切，可选90度等画面方向；主摄另有ARCore模式。
- 控制、设备、网页遥控、空间观察、抓放、感知与避障工作区共用一个被动手机预览。它只复用既有采集，不开启另一手机／UVC拥有者。
- “保存当前观察”要求实际显示帧的会话与序号；保存原JPEG、深度预览、float32原数组、SHA-256、镜头和深度来源。历史影像有独立保存时间；旧会话、过期帧与未指定帧不能保存。
- 交互点云可旋转、平移、缩放、调整点大小，使用同帧RGB着色。实时相机空间与历史AR会话空间分开；旋转后的深度先还原相机轴再应用AR位姿，未建立机器人外参时不生成虚构机器人轨迹。
- 原空间地图追加本轮运动／四镜头／深度失败证据，原地图快照及复核保留。发布检查点为56条观察、9个标记，15张新增图片经HTTP逐字节SHA核验。

镜头名称说明相机接口，不代表安装方向。当前前置看到机体内线缆和板件，不能当作车后地面；超广角增加前方范围，但未解决车后近轮盲区。四镜头是轮切实测，不声称并发四路。

## 真图和空间质量

四个镜头及恢复主摄均在新API中取得至少5张不同新帧，五张存档JPEG的HTTP回读SHA与原字节一致。车载质量补丁发布后恢复主摄彩色，独立SSH核验25张不同新帧，末次帧龄65.7ms、720×1280；该帧龄不是已测光学端到端延迟。当前手机仅红米启用，iPhone未参与本轮实测。

旧任务40组RGB-D构成的50,654点着色云已导入本地空间存档，可通过原网页交互查看。它属于旧AR会话，未配准到当前机器人位置；AR尺度、地面／台阶和回环尚未验收。

本轮三段前移后保存了4组真正的自动深度输出，但原数组均为约20.284—26.426m，0.2—5m内像素和展示点数均为0；原始深度高置信覆盖亦为0。正值比例100%不能解释成测距成功。原数组仍保留，零点存档不标为可用空间模型；界面分别显示正值覆盖、分析范围覆盖和原始置信度。raw置信度不冒充自动深度置信度。此次发布不宣称可靠SLAM、米制定位或自动放行避障。

## 持续探索与保护

原平台 `/api/platform/fieldmap/exploration` 保存会话、阶段、心跳、运动计数和用户授权；状态明确为助手监督有限动作。该模块不自行产生轮速，不授予电机权限。网页统一显示持续探索横幅与停止按钮；停止先持久锁定disabled，再请求原控制服务agent／servo停止，旧会话不得恢复动作。停车是否完成仍须实时回读。用户聊天说“停止”同样优先执行此停止流程。

发布前物理检查点：3个名义5cm前移段均完成，轮估合计0.148011m；2次实际左转尝试，1次完成、1次74/20计数不对称停车，计划中未执行的脉冲不计尝试。根因未定，不反复强行重放同向转动，不放宽不对称门。头部换角度观察不代表已确认整车旋转包络。

一次头部观察在0动作时被静止轮10的11.4V读数拒绝；随后4份新读均11.9V、双轮零速零目标卸力且位置稳定，重新预检后的7步头部扫描通过。保留失败回执，不认定已查明供电或传感器故障。右肩抬升原物理hold仍保留，未进行右抓取、ID／模式／PID／零点／固件变更。

后续补充7步中等俯角头部扫描、左腕小幅俯仰与收臂肩水平外转2步均通过，无contact；侧下方UVC画面严重欠曝且车体遮挡，数值增亮无法恢复已截断的暗部。手机主摄仍正常，欠曝根因未确认；此时底盘维持停车，不将新鲜黑图、无碰阻或软件通过当作已确认通路。

旧后退1m授权已消费0.92m，且航向已变化；不重置消费、不将剩余额度用于新方向盲退。后续移动必须来自本次新图、整车净空与有限动作，用户停止及人员／源龄／温压／不对称保护始终优先。三段前移不能当作转向异常已解除；尚未进入过道。
