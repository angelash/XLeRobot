# 2026-11-11 实时避障行人提示兼容性修复

用户提供实时避障状态截图，要求检查并处理。以下区分软件故障、实际部署和仍缺少的物理标定；本轮没有机器人运动。

## 原因与处理

车载 `.venv-debug` 安装的是 `opencv-python 5.0.0.93`，实际 `cv2.__version__` 为 `5.0.0`；本机构建没有 `HOGDescriptor`、默认行人分类器和 `calibrateHandEye`。原代码因此关闭行人提示；相机输入、地面外观处理和闸门消息仍在更新。这是运行依赖不兼容。

另一条“未完成地面标定”有独立原因：原自主学习台账的标定列表为空，没有头部地面单应或对应导航头位。不能把它当成报错隐藏，也不能拿手机 AR 点云、轮位估计或默认相机高度生成已验证标定。地面外观学习的 23,288 个像素样本只描述颜色，不提供米制比例。

修复如下：

- 项目依赖改为 `opencv-python>=4.11,<5`，新增实际构造并调用 HOG 的原生依赖回归检查。
- `start-platform.ps1` 优先使用存在的 `.venv-studio/Scripts/python.exe`，否则沿用 `.venv-debug`；仍为原 8770 Studio，不新增服务、端口或开机任务。
- 本次在车载创建 `.venv-studio`，单独安装已校验的 `opencv-python-headless 4.11.0.86`；NumPy 2.4.6、FastAPI 等依赖通过该环境的 `controller-dependencies.pth` 复用原 `.venv-debug/Lib/site-packages`。这是视觉依赖隔离，不能称为其他依赖也完全独立。
- 原串口控制进程继续使用原环境，不替换它正在加载的原生库。Studio 原启用的感知和 Android 采集在停稳、任务空闲时停止，重载后按原配置恢复；iPhone 保持停用。
- 页面能力说明改为实际检测频率及状态，明确“未检出不代表没有行人”，避免恢复后继续固定展示 OpenCV 5.0 的旧限制。

运行目录不进 Git。以后重建环境时应安装兼容的 OpenCV 4.x，并用 `cv2.__version__` 和 `cv2.__file__` 验证实际导入位置；本次复用路径不等于可以删除 `.venv-debug` 或 `.venv-studio`。两套环境的包元数据可能同时可见，不能单凭共享目录中的 `opencv-python` 元数据推断 Studio 实际加载版本。

## 部署与核验

工作端 75 项、车载 Studio 环境 75 项检查通过，另有实时避障页面 DOM 检查通过。覆盖原生 HOG 调用、未标定不输出距离、感知断流／头位偏离、避障闸门、平台 HTTP 和 Windows 部署脚本解析。

先核对四个发布文件的旧版本标准化 SHA，再备份、发布、在车载回归，最后只重载 Studio。四文件原始字节 SHA 读回一致；既有控制 PID 35476 保持。地图、手机配置、原设备标定及感知配置／地面模型共五个保护文件的 SHA 保持一致，资产计数保持 0／0／0。

发布首轮实际输入 20 新帧、发送 17 条闸门消息、0 发布错误，状态返回“可用（每0.5秒）”；源帧龄 112ms，处理 P90 38.53ms。这些数值只代表该窗口，不是行人识别准确率或相机曝光到停车的绝对延迟。

后续22.92秒／40次只读复核：新增261输入帧、193次发布，0发布错误，采样时输入源龄最大137ms；Android 40次均有新鲜可用帧，三轮×三路UVC快照均成功。16电机在线，双轮仍为3225／1369、零速／零目标／扭矩0，标定列表仍为空。另一个独立进程在真实头部图上首次构造并调用HOG耗时1095.28ms，包含冷启动和该进程默认线程配置；不能用Studio滚动P90代替最坏单次耗时。原源龄／消息350ms闸门仍按实际时间检查，没有为恢复模块而放宽。

私有证据位于工作端及车载 `.local-deploy/perception-20261111/`：依赖探针、发布清单、回归输出、回执、备份路径和持续运行复核。检查脚本最初因长 EncodedCommand 和外部脚本导入路径失败，后改为上传脚本、显式设置工程 PYTHONPATH；失败回执保留，不算产品验收通过。

## 地面距离仍待真实标定

当前仍为 `metric=false`、`clear_m=null`、闸门阻断。需要在固定头部导航姿态下，取得位于地面且相对车头中心有实测坐标的棋盘格或参考点，计算并检查单应误差、记录当时头位，再由用户采用；流程沿用[实时避障说明](OBSTACLE_PERCEPTION_ZH.md)。之后还要按 O1／O2 检查距离误差及白色／同色障碍漏检，才能评估避障行驶。

本轮只恢复行人辅助检测模块；没有实物行人检出率、地面距离精度或自动驾驶验收，也没有修改已审核控制规则。
