# 手机视觉技术落地实测

日期：2026-11-09。承接[手机视觉方案](PHONE_VISION_PLAN_20261109_ZH.md)。用户说明设备均已连接并授权尝试；本轮仅检查设备、接收手机画面并调用原平台图像质量分析，没有机器人动作，没有修改控制阈值或重启机器人服务。

**结论：红米 K60 至尊版的有线 RGB 采集及送入现有 Studio 分析已实测可用；iPhone 12 的 USB 信任、设备通信和 Windows 接收库已核验，但手机端尚无深度流，未取得 RGB-D。两台手机实际都接在工作端 ASH-LAPTOP，尚未迁移到车载笔记本 USB。**

## 1. 系统与设备核验

- **红米实机：** `23078RKD5C`／`corot`，系统报告 Android 16、SDK 36、`OS3.0.305.0.WMLCNXM`。ADB 已授权，USB 配置报告 `adb`。枚举得到前后镜头；本轮使用后摄 ID 0。没有查到已安装的 ARCore／第三方摄像头采集 App，ARCore 能力尚未验证。
- **iPhone 实机：** `ProductType=iPhone13,2`（普通 iPhone 12）；设备实际报告 `ProductVersion=27.2`、`BuildVersion=24B119`。版本字段是当次设备返回值，未额外解释为公开发布状态。Apple USB 驱动和设备服务正常，已有信任有效；仅筛选摄像头／深度工具的 App 元信息，没有读取相册、文件或 App 数据。未发现 Record3D 等目标采集工具。
- **连接位置：** 工作端 USB 同时识别两机；车载 SSH 复查未枚举到这两台 USB 手机。原三路机器人 UVC 保留。
- **接收环境：** 复用工作端现有 ADB 34.0.3 服务；单独下载 scrcpy 5.0.1 Windows 官方包，SHA-256 与官方清单一致；`record3d 1.4.1` 和 `pymobiledevice3 11.50.3` 安装于忽略目录内的隔离虚拟环境。没有全局升级 Python 包，没有安装手机 APK，没有安装或替换驱动。

## 2. 红米实际取得了什么

首轮用官方 scrcpy camera 模式取得 12 秒限时视频，解出 **166 帧，1280×720，容器标称 15fps**。它是后摄输出，不是屏幕截图；实际保存片段时长约 11 秒，起流耗时包含在限时窗口内。人工查看样图，能看到桌下线缆与支撑结构，证明镜头产图；当前机位不能证明已看清机器人、目标或桌面接触关系。

随后实现[可重复执行的 USB 接收探针](../../deployment/phone_vision/README_ZH.md)，直接接收 H.264、用 PyAV 解码，周期性向原车载 Studio 发送单帧分析：

- 实际连续接收：**901 帧／60.031 秒，14.992fps**。
- 源时间戳跨度：59.996 秒，推算源输出 **15.001fps**；本轮源 PTS 全部严格递增。
- 首帧：启动后约 1.437 秒。
- H.264 负载：约 **3.994Mbps**；单包解码耗时 p95 约 **16ms**。
- 主机相邻接收间隔：p95 约 **79ms**，最大 **187ms**。采集循环还执行 JPEG 保存与少量同步 HTTP 请求，因此这项不是纯 USB 传输抖动，也不是端到端成像延迟。
- 手机电池：初读约 19%／37.0°C，结束约 22%／33.8°C，USB 供电；这是两个时点的系统读数，不能替代长时间热稳定或充电能力验收。

期间没有屏幕投射、声音采集或机器人控制。测试结束后本次转发为空，未留下该次 scrcpy 主机进程；没有建立额外端口站点或开机任务。

## 3. 原平台接入验证到哪一步

数据路径是：**红米后摄 → USB／ADB → 工作端 Python 解码 → 局域网 HTTP → 车载 Studio 8770 的既有图像质量接口。**

连续试验中 4 张新帧均由 `/api/platform/vision/quality` 正常返回质量结果，分辨率均为 1280×720；HTTP 请求往返分别约 187、172、125、110ms。这些数值不含完整相机曝光至控制器使用的时延，不能称为“视觉闭环延迟”。首轮另有一张样图独立请求返回 HTTP 200。

当前画面亮度约 101／255，Laplacian 方差约 58–59；原接口给出细节不足的启发式提示。画面中近处线缆、安装角度、目标距离、对焦和纹理都可能影响该统计，不能单凭这个分数判定相机差或自动对焦失效。

**已通过的是视频采集、主机解码和原平台分析接口；尚未提供 Studio 手机实时直播入口，也未接入抓取、避障、训练或三维定位。** 本轮没有重启控制器或 Studio，没有改变原相机消费者。没有把零星图像质量请求当成持续语义识别。

## 4. iPhone 具体卡在哪里

已验证：USB 枚举、Apple 驱动／服务、已有信任、系统属性读取、Windows `record3d` 库导入和 1 台 USB 设备枚举。

实际尝试 Record3D RGB-D 会话时，`connect=false`，底层返回 usbmux `Connect failed, Error code=3`，帧回调为 0，没有 RGB 或深度数组。结合未发现对应 App，当前可确认“没有可接收的 App 深度流”；不能据此判断 TrueDepth 硬件坏、Windows 不支持或该版本永远不兼容。

已准备[限时 RGB-D 接收探针](../../deployment/phone_vision/iphone_usb.py)。下一步需要在 iPhone 端安装并打开 Record3D、允许相机、开启 USB Streaming mode 并启动采集，才能继续测真实深度。若要求付费，应先核实价格和功能，不自动购买。用户已通过本轮异步消息收到具体操作说明。

## 5. 调试与检查记录

- 第一版直接 socket 接入遇到提前关闭：ADB TCP 转发已接受连接，不代表手机 abstract socket 已就绪。改为等待 scrcpy dummy-byte 握手后才读视频。
- 下一版解码报错：scrcpy 5 的协议区分 session header，config／keyframe 标志改用 bit 62／61，不能套用旧版布局。按本次版本源码／文档修正后完成 60 秒试验。旧失败回执保留，不隐藏为“首轮即成功”。
- 5 项生成数据协议边界检查通过，Python 编译检查通过；不涉及真实硬件动作测试。
- 原图、视频、设备标识、回执和日志保存在忽略目录 `.local-deploy/phone-vision-20261109/`。公开文档只记录必要硬件能力和聚合结果，不提交手机序列号、私人画面或配对凭据。

## 6. 实施判断

**红米可以继续投入“有线辅助相机”的工程接入。** 手机端无需先安装 DroidCam，本轮已通过官方 scrcpy camera 服务走通 USB 视频；后续要把限时探针改成有源龄和断线状态的受控采集适配器，并接到 Studio 视觉页。移动到车上后，车载 USB 带宽、CPU 解码开销、供电、安装视角和线束仍需重新测。

**iPhone 继续保留为近景深度候选。** 电脑端接收准备已完成，先补手机采集 App，再决定是否值得做标定与部署。当前结论不支持宣称已获得数值深度、已改善抓取成功率、已实现全向观察或自主避障。
