# 手机视觉接入与上车测试

日期：2026-11-09。承接[设备方案](PHONE_VISION_PLAN_20261109_ZH.md)与[手机取流实测](PHONE_VISION_TEST_20261109_ZH.md)。用户要求先完成技术对接，手机固定在机器人并接好后可以直接启用视觉测试。

**软件已集成到原 XLeRobot Studio 8770：主导航“手机视觉”，地址 `/#phones`。支持启停、彩色／深度预览、深度像素原值、断流隐藏与重连。车载电脑当前休眠离线，尚未安装这次更新；已准备并验证离线安装包，下一次唤醒后仍需完成车载安装与 USB 授权，不能把工作端联调写成车载部署完成。**

## 1. 手机装上机器人后的操作

1. 把两机固定在车体支架，视野覆盖工作区；数据线接**车载笔记本**，不再接工作端。先保留双臂和底盘不动，确认线缆没有拉扯或遮住镜头。
2. iPhone 解锁，首次接车载电脑时选择信任；打开 Record3D，选择前置 TrueDepth、开启 USB Streaming mode 并**点击开始采集**，保持 App 前台。
3. 红米开启 USB 调试，首次连接车载电脑时解锁并接受该电脑的授权；关闭占用相机的其他 App。无需另装摄像头 App。
4. 打开原 `http://192.168.137.150:8770/#phones`，检查页面“当前采集电脑”确实为车载机，分别点“启用测试”。当前连接哪台电脑决定在哪里采集，网页所在的浏览设备不承担 USB 采集。
5. iPhone 应出现彩色与深度两幅图；红米出现后置彩色图。先检查人物／物体和桌面是否完整可见；点击深度图可以读原始像素数值。固定机位后再进行已知距离对照和机器人坐标标定。

首次信任、安卓 USB 调试授权和 Record3D 开录是手机操作系统／App 的实际要求，页面不能替代。开机不会自动开始手机采集；一次点“启用测试”后，后台会在手机暂时断开时尝试恢复，点“停止”结束。重启平台后需重新点启用，避免无操作采集。

## 2. 已实现的技术对接

- 原 Studio 进程挂载 `/api/platform/phone-vision/*` 和 `/phone-vision/view`，加入主导航及能力目录，没有增加用户访问端口或启动任务。
- 每台手机各用一个 Studio 管理的采集子进程，原生库与平台 Python 环境分开；苹果、安卓可以分别启停。只取手机摄像头，无音频、屏幕镜像、相册读取或电机指令。
- iPhone 回调内复制同包彩色／浮点深度，保留内参和空置信度状态；通过有大小上限的本地管道发送彩色JPEG、深度预览及数值数组。预览限为约8fps以内以减少开销，状态中的接收频率来自采集回调，不是预览刷新率。
- 红米使用已验证的 scrcpy 5.0.1 camera协议及 USB ADB。禁止任意页面传入执行路径；本地工具位置来自私有配置或安装包。遇多个已授权安卓设备时不猜设备，提示只保留目标手机。
- 每次启动／重连使用新的会话编号。页面、图像和深度查询绑定会话和帧号；旧会话、重复序号或超过1秒的新鲜度窗口均拒绝。停止、失联和错误会清除旧帧，不用历史画面冒充实时画面。
- 采集异常时按有限间隔重试。停止状态会等待旧进程退出，避免同一相机出现两个所有者。Android异常退出后的清理只针对该会话独有转发和临时文件，不重启 ADB、不动其他转发。Studio退出也会关闭它管理的手机采集。

## 3. 车载离线安装

完整包由[打包工具](../../deployment/phone_vision/prepare_kit.py)生成，包含 Windows x64 便携 Python 3.11.9、固定版本 NumPy／OpenCV／PyAV／Record3D、Google ADB、scrcpy server、接入源码、签名验证后的 Apple Mobile Device Support 安装材料及逐文件SHA清单。

1. 下一次车载机唤醒后，把完整包解压到本地；先检查原平台没有活动采集／录制，保留控制器与运行数据。
2. 运行 `INSTALL.cmd` 或用包内Python执行 `install_kit.py --robot-root D:\Robot\XLeRobot`。它先校验包内全部文件、加载采集依赖，并比对每个目标源文件；发现其他源码修改就停止，不覆盖。安装保留原地图／配置／标定，写带时间的源码备份和回执。
3. iPhone首次接车载机若缺Apple USB支持，可在车载机以管理员运行 `INSTALL_APPLE_DRIVER.cmd`。它再次核对MSI的哈希与Apple签名，仅安装Apple Mobile Device Support；已有设备服务时跳过。本轮只准备材料，未在工作端安装或替换驱动。
4. 依原流程仅重载 Studio，不重启串口所有者。随后确认主导航、状态接口和两机新帧；核对原地图／配置与控制器仍正常。若源码发生冲突，先合并再发布，不为方便安装回滚车载的其他修改。

便携依赖放 `.local-deploy/phone-vision-runtimes/<包版本>/`，不升级原控制器虚拟环境。安装器不自动重启服务、不启用手机、不发动作、不启动独立系统服务。Apple驱动安装可能要求重启，应先读安装回执；不能承诺任意Windows驱动状态都完全免配置。

## 4. 本轮验证与边界

- 自动化检查覆盖：会话／帧号隔离、过期图和过期测距拒绝、停止清帧、重连状态、非法来源／超限数据拒绝、数值深度与空置信度、分段管道写入、模拟iPhone采集、安装包损坏及目标源码冲突。模拟数据只用于工程检查，不是新增物理测距证据。
- 工作端在**原8770 Studio**实际显示红米后摄，浏览器完成启动、停止隐藏、重新启用新会话；桌面与390px窄屏均检查，没有页面脚本错误。iPhone像素点击使用生成画面验证，真实iPhone当时已断开；前次真实USB RGB-D约30fps证据见实测报告第7节。
- 便携Python3.11依赖加载通过，且已实际驱动工作端红米取景。安装演练在生成的目标目录通过：逐文件回读、生成的私有数据哨兵保持、工具配置生成、用户修改拒绝；没有安装到离线车载机。
- 主动中断精确的Android采集进程后，状态曾隐藏旧图并恢复到新会话；这证明进程故障恢复路径，不等于已验证真实USB反复拔插。异常会话转发清理另有精确作用域检查。
- 重载的是工作端Studio；原2条录制、1条姿态、1条实验配置数量保持。未重启工作端串口所有者，也未唤醒休眠车载机。

尚待上车验证：车载USB总线带宽／供电、Session0的Apple驱动访问、车载CPU负载与热稳定、两手机同时长时取流，以及固定机位后距离误差、内参／外参／镜像关系。显示深度原值不代表准确率或已完成机器人坐标定位。该模块目前只启用视觉测试，不接通自动抓取、行驶或避障门控。
