# 车载自行决策，模型按周期或条件观察

用户2026-11-17再次纠偏：机器人应自行探索，助手只定时或根据条件查看反馈。此前12次前移虽然由本地执行，下一段通路与距离仍由助手决定，属于监督移动；不能因为电机循环没有模型调用就称为自主探索。

本次把可执行动作选择、状态监测、驻点扫描、源恢复与进度汇总放进既有Studio的车载状态机。**实时几何导航仍未接通，自动底盘平移／旋转均关闭。** 本次验证覆盖自主调度和驻点采集，不把它写成整空间自主导航已经完成。

## 当前能力与接口

- 实现：[autonomy.py](../../../deployment/fieldmap/autonomy.py)，挂载在原8770的`/api/platform/fieldmap/autonomy/*`，复用原[LocalScan](../../../deployment/fieldmap/local_scan.py)和8765唯一串口拥有者。
- `POST /autonomy/start`只接受任务授权、探索会话和有限时间策略；不接收距离、方向、waypoints、`navigation_ready`或净空放行开关。模型不再为每个头扫或5厘米移动提供批准。
- `GET /autonomy/status`提供当前阶段、具体阻断、真实新增视角、驻点数、周期摘要、停止锁与已实现能力。`GET /autonomy/{id}`提供完整回执与带序号的事件。
- 原空间观察页显示自主任务阶段、进度、汇总周期、具体阻断和停止入口；仍在同一导航与应用内，没有新增站点或开机服务。
- 页面、总探索与本地任务停止入口先锁住调度，再调用原停止。调度占有执行器时，其他本地批次不能插入；人工／网页接管仍优先。

## 本地决策周期

任务启动后，车载自行读取原硬件、停车窗口、共享相机和手机／标定状态。头部以外的编码器、控制PID和操作者参考构成驻点依据；出现非预期位移或参考变化时锁定停止，头部正常扫动不使驻点失效。

1. 其他任务、接管、参考改变或保留故障：`latched_stop`，保留原因与旧回执，不自行重放。
2. 硬件／停车窗口不足：`waiting_hardware`，不发目标，等待新读回。
3. 关键源不新鲜：`waiting_source`，原地等待恢复。
4. 当前驻点未完成观察：自行建立原生观察依据并发起`head_layers`，不等待模型看图批准。
5. 每张实际新视角更新进度；源中断恢复仍在同一个本地任务中续接，完整18视角后保存原Studio图集。
6. 缺少实时导航能力：`waiting_navigation`，列出测距、定位、外参、实测包络与导航后端缺口；不改用模型逐段放行。
7. 有限时间到期：`budget_reached`，停车并保存未完成任务，不宣告地图完成。

默认每秒读取一次决策输入，每60秒生成汇总；180秒没有有效新增观察时生成一次无进展事件。视角真正增加才更新进度时间，轮询、心跳与重复查看不计为新覆盖，未测量的新区域面积保持`null`。模型可以按摘要或异常调整策略；本次没有新增后台模型自动调用或应用级计划任务。

任务默认900秒，上限3600秒；实机软件验证采用300秒。源龄／电机／停车保护仍在原执行器内独立运行，不依赖模型定时查看。当前不报告米制覆盖率、全屋完成、返程或窄出口通过。

## 断流恢复与停止边界

原800毫秒相机门保持。头部动作中关键源失效，先调用原拥有会话的停止入口，再保留原动作请求的结果；HTTP超时不自动重发。

仅在原动作结果完整、无contact／硬件结束原因、停车与16电机新读回通过、其他姿态／操作者参考未变化时，才进行头部源恢复。连续三组新帧稳定后，按当前实读位置重新拆分到尚缺视角的路径；已经保存的视角不重复计数。每任务最多10次有界源恢复，每次等待最多8秒，原任务总时限仍约束全程。

接触、无法解释的执行器结束、结果未知、停车未确认、控制器／操作者变化、用户停止或原物理hold不会由源恢复清除。右肩抬升hold保留，头扫只使用head:7／8，不以当前任务为由驱动该肩或写电机模式／PID／零点。

原伺服入口的运行ID在活跃状态下读取；会话建立请求尚未返回时，使用本任务唯一标签识别归属并保留原停止能力。标签只在本地生成，不由客户端提供；外部会话仍拒绝。

## 实机发现与修正

- 首轮自主任务因互斥识别错误提前停止。原`ServoSession`设置`LimitSelfTest.running=true/current=servo`，不能只看`running`就认成其他自检；修正为核对精确会话／任务标签及占用类型。
- 首轮没有完整登记头部步骤，但最终头部两个编码器各变化约−11计数；不能把空回执当零运动。双轮与其他关节新读回未变。原记录与不完整尾段保留，软件误判复核后从当前姿态建立新参考，没有清除物理hold。
- 第二轮本地自行完成6视角，随后相机超出800毫秒门。原中断动作完整返回、无contact，原地停车通过；旧实现将该源中断作为整轮失败。新增同任务头部源恢复与剩余视角续接，旧6视角和失败事实单独保留，不并入新软件验证的完成分母。
- 两次软件中断均通过确切运行ID、原始回执、无活动执行器、完整停车窗与当前姿态复核。复核只结束已查清的软件原因，旧任务记录不改写成成功；没有通用“清空hold”接口。

实机最终结果与私有证据范围见[公开回执](AUTONOMOUS_DECISIONS_RECEIPT_20261117.json)。此前半米移动阶段的[原归档](EXPANDED_MAPPING_RECEIPT_20261117.json)保持独立截止，不把后来的自主调度归入当时的证据包。

修正后的第三轮由车载自行选择并完成18视角，23个完整头部步骤、18份手机RGB，扫描任务耗时66.610秒，父任务从启动到登记完成71.141秒；模型逐段批准次数0，双轮没有旋转／平移命令。新图集`104a286739054aafb99cf9ad9aea26ef`保留235度／缺125度的驻点照片方位，未认证真实360度或度量空间。该轮未发生源恢复，不能把程序中的恢复回归写成实机已经触发恢复；第二轮断流／6视角保持原失败记录。

本地汇总分别在60.812／121.250／181.828／242.453秒生成，252.109秒时按180.968秒无新增覆盖上报一次；300.703秒按本轮时间预算结束，探索意图保留。周期监测的低频／不均匀读包偶尔不足三个样本的原停车窗，状态会暂时显示等待停车窗口，再回到等待导航；不将这种采样不足解释为已证实机械故障，动作前仍重取原完整窗口。最终独立读回16电机及停车窗通过，双轮3899／716、零目标／扭矩0，无活动动作。

## 可靠几何仍是下一项能力缺口

新停车AR复查取得8份新`TRACKING`样本，4份有数值深度，中位14.180／26.037／22.271／31.882米，0.2—5米比例均为0，与近处家具不符。保存原始RGB／数组后恢复原camera0／90度普通彩色采集；没有修改字节序、套用Camera2 DEPTH16掩码或伪造距离。跟踪成功与`rgbd=true`不能单独证明数值可信。

原米制模块目前是`known_pose_replay`，`localization_backend=not_connected`。已有占据栅格、障碍膨胀、frontier与A*属于回放／预览能力；本次不从已保存地图中挑一份，伪装为当前场景。C2地面单应、手机到底盘外参、整车包络与连续定位均未验收。

接入真实行驶闭环时需要完成：

1. 可信距离来源：验证原始单位、量程、误差和缺测；C2路线需固定导航头姿、实测参考点及原采用流程，不能使用默认相机高度生成距离。
2. 同一参考与定位：采用传感器到底盘外参，保留源时间与AR／定位epoch；建立连续位姿、质量和不连续检测，人工接管／换位／重定位不得静默拼接旧图。
3. 实时占据层：由真实匹配的深度／位姿更新已见自由、占据和未知；动态人员另层处理，缺测不清空障碍，旧数据有时效。
4. 本地选路执行：复用现有几何frontier选择可达自由区内的观察位，按实测全车包络检查每段扫掠；原有有界轮控与独立停车守卫继续执行。模型不提供自由空间标签或逐段批准。
5. 现场验收：新区域面积／细节覆盖、动态临停后自行恢复、失定位停车／恢复、窄段避碰、闭环与返回原点分别留证。回放、程序测试和驻点18视角不能替代这些结果。
