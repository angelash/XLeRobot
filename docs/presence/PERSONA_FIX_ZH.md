# 展示角色人设接入修正

日期：2026-11-02。用户反馈：对话没有带入MOSS人设。

## 原因与实现

现场角色名为MOSS，人设配置正常；但真实问候回复“我是车载小九AI助手”。此前展示适配器只把角色名和“仅影响措辞”的风格拼进普通用户消息，会话桥又固定前置“你是车载小九AI”，未明确把MOSS作为应用角色身份。

现在展示页发送用户原文，并通过独立`presentation.name/persona`字段传递本轮配置。会话桥校验、持久化该快照，并交给对话引擎。展示角色指令明确采用当前角色第一人称；每条消息还显式附带最新角色配置，覆盖历史轮次的旧角色。修改名称或人设后，下一条消息生效。普通工作端消息继续使用原身份。

真实引擎初次验证发现：只调整启动参数、继续旧会话时仍可能沿用旧角色，LUNA测试得到MOSS自称；该版本没有作为最终方案交付。补充每轮角色上下文后，在原本以车载小九开始的同一会话中，MOSS问候得到“你好，我是 MOSS。很高兴与你交流。”，随后自定义角色改为温暖问候。最终还需以实际8770对话核验身份与自定义表达。

角色设置不提供动作授权，观察/规划限制与只读沙箱保留；不更换账号全局配置、基础模型指令或持久会话ID。请求ID的幂等校验包含角色快照，不能用同一ID替换角色或消息。公开过程回执只显示用户原文与回复，不显示整段人设。

## 验证与发布

- 本地回归覆盖真实HTTP链路中MOSS/自定义设置到会话桥的传递、下一轮更新、持久化、幂等、公开回执隔离、无效配置拒绝，以及新会话/延续会话的角色指令和只读权限。
- 独立真实引擎验证使用临时会话目录，未替换生产会话；保留初次失效和修正后的回执。
- 车载发布及实际对话结果在验收完成后补充；既有语音开关与用户配置按发布前状态保留。
