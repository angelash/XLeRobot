# 语音输入与常驻对话首版交付

日期：2026-11-02。用户已批准按[设计](VOICE_INPUT_DESIGN_ZH.md)开发，并明确要求本轮不做有声音的测试。本文随实现与部署结果更新；真实拾音、唤醒准确率、回声和扬声器效果由用户验收。

## 使用方式

1. 在机器人笔记本打开 **http://127.0.0.1:8770/presence/**。原LAN入口仍可看状态、用文字对话；不会采工作电脑的麦克风。
2. 顶部“语音输入”默认关闭。点击后授权并明确选择Realtek实际麦克风阵列，再点击“开始监听”。立体声混音、Pico等已识别的回放/虚拟音源不可选；设备ID只保存在该浏览器本地。
3. 可按住“按住说话”，或呼叫当前角色名字。MOSS支持英语MOSS及中文“莫斯”；设置中的“唤醒发音别名”支持中文、词典覆盖的英文名字。无法编码的名字会明确提示，可用别名或按住说话。
4. 首版默认“识别后确认再发送”：查看、修改识别文字，点击“确认发送”。设置中可取消此项，改为最终转写自动送入角色对话；没有置信度分数的识别结果不会显示虚构分数。
5. 输入与声音输出独立。开麦不会打开声音；旧用户的输出开关/声线保留。声音开关需在当前页面启用声音后才播放新回复，另有“停止播报”和“取消回答”。
6. 输入关闭、页面隐藏/退出、设备失效、连接中断或角色/输入设置改变都会结束本次采集，需要显式重新启用。关闭输入不会取消已接受的对话。

## 实现范围

- 浏览器AudioWorklet单路采集，请求AEC/降噪/AGC并读取实际设置；有状态64tap低通重采样为16kHz单声道PCM16，每帧20ms。处理节点输出全零，并用零增益连接，不把麦克风直通扬声器。
- 在用户点击中先解锁采样上下文；AudioWorklet加载3秒未完成时，使用同一滤波器的兼容采样图并明确标注“兼容采样模式”，避免一直停在准备中。兼容图的主线程调度更易受3D争用影响，仍通过有界传输/断帧规则拒绝残缺指令；真实笔记本浏览器的模式和并行负载表现由用户实测。
- 同机WS仅接受本地可信页面和单一`owner_id + capture_epoch + token`租约；约900ms心跳、3秒失效。检查帧格式、连续序号、实时速率与有界队列；异常丢弃整条未提交语音，不重连重放。
- 设备内sherpa-onnx KWS、Silero神经VAD与流式中英Zipformer ASR在工作线程运行。1.5秒预滚保留同句指令；启动等待5秒、约500ms尾静音、20秒上限；原始音频只在有界内存中，不保存录音。
- 名字和发音别名逐项校验。更名时关闭旧租约并清空未提交采集，重新启用时原子加载新词表；已接受任务保留提交时的角色快照。
- 精确白名单只处理停止播报、闭麦、取消回答、收起/展开过程。普通文本进入原有观察/规划角色对话，没有任何电机/扭矩/行驶写入通路。
- 首版半双工：回复播放时暂停KWS/ASR并清预滚，结束后约300ms恢复。缓存唤醒短句独立处理，暂停回声期间保留纯呼叫后的倾听会话；未缓存、声音关闭或继续说话时只显示视觉反馈。不承诺播报中语音打断或关网页后监听。
- Onboard常驻stdio引擎依协议完成轮次，保留独立工程/展示线程、原ID幂等、故障锁定与不重放。公开回复增量和语音状态进入同8770 SSE，部分转写/字符进展只更新有界内存。
- 按稳定公开句子合成，播放上一句时可预取下一句。历史、演示、隐藏页面不补播；停止/取消/切角色丢弃迟到音频。只完成了一部分的回答明确为中断。

## 可复现准备

使用运行Studio的Python安装`presentation/requirements-voice.txt`，再执行：

```powershell
python -m presentation.prepare_voice_models --root <presence-data>/voice-models
```

官方模型URL及本轮下载字节SHA-256固定在`presentation/voice-models.lock.json`。若企业TLS导致Python下载失败，可用Windows受信下载器取得锁文件对应三个文件，再添加`--archives <下载目录>`；仍会校验全部下载字节。只提取固定白名单的INT8模型文件，另存逐文件SHA清单，不执行归档内路径。模型、下载包和缓存不入Git。

模型分别为`kws-zipformer-zh-en-3M-2025-12-20`、`streaming-zipformer-small-bilingual-zh-en-2023-02-16`的INT8文件、`silero_vad.onnx`。运行库固定sherpa-onnx/core 2.0.1、pypinyin 0.55.0、sentencepiece 0.2.1。sherpa-onnx库为Apache-2.0；模型权重许可需以各原发布页为准，本轮未能读取Hugging Face模型卡，不把库许可自动当成所有权重许可。权重仅留设备本地，没有随源码分发。

## 静默验证与限制

本机76项Python、23项Node检查覆盖配置兼容、默认关闭、帧顺序/格式、租约争用/接管/超时、名字切换、最终文字确认及幂等、白名单、取消/迟到结果、公开输出过滤、按句去重、状态恢复和重采样抗混叠。车载初轮75通过/1失败发现Windows回执读取与原子替换竞争，新增邮箱/会话文件锁及4并发读者回归后，车载77项全部通过；唯一警告为测试工具anyio BlockingPortal别名弃用，不是产品异常。

Playwright使用生成的假麦克风/音频节点：验证默认零采集、权限拒绝、虚拟输入禁用、转写可编辑并只提交一次、关闭释放、改名停采、桌面/390px布局。播放调用和语音合成请求均为0；没有打开物理麦克风。

另以真实浏览器音频图、生成的恒零MediaStream、静音浏览器验证采样→滤波→WS→服务端：兼容路径连续收到至少25帧，每帧640字节、全部为零，关闭后租约释放，播放调用0。本工作端Chromium149/156的最小AudioWorklet模块均等待不完成，故不记为真实AudioWorklet已通过；保留失败证据，兼容路径通过。代码滤波与AudioWorklet消息包装分别由Node/模拟浏览器验证，用户实际麦克风测试仍待完成。

车载隔离常驻引擎连续MOSS与LUNA身份问候使用同一进程，分别得到“你好，我是MOSS。”“你好，我是LUNA。”；公开增量/完成分别约18.424/18.609秒、3.048/3.161秒，并通过取消后不返回成功。首轮仍可能有明显冷启动或模型/网络等待；只有2条短答，不能报p95或承诺固定提速比例。没有使用生产角色线程，也没有将测试回复送到生产页面或TTS。

车载模型首次加载约6.515秒，5秒全零PCM推理约0.573秒，输出事件0；中文自定义“露娜”词表准备通过。该结果只证明模型初始化/静音处理，不证明人声识别、近距离唤醒命中率、背景误唤醒、AEC或车载并行CPU预算达标。本轮没有录制或播放真实声音，没有相机采集或机器人动作。

发布状态、文件验证、服务与配置保留结果在完成部署后追加于本文末尾及PROJECT_STATE。
