# 展示消息发送与 MOSS 吊顶关节修正

日期：2026-11-02。用户反馈底部消息发不出去，MOSS 整个吊顶与机身一起转动不合理，要求顶部固定、机身独立转向、机械臂随关节适配。

## 消息发送的原因与修正

在车载 `http://192.168.137.150:8770/presence/` 实际核验：`isSecureContext=false`、`crypto.randomUUID` 为 undefined，而 `crypto.getRandomValues` 可用。旧代码在提交请求前调用 `randomUUID()`，普通局域网 HTTP 页面因此在浏览器报错，根本没有发出 POST。

新增 `request-id.js`：安全上下文继续使用 randomUUID；普通 HTTP 用 getRandomValues 生成 128 位随机请求 ID，保持已有格式校验、稳定请求 ID 查询与不自动重发的语义。生成失败会显示明确错误。没有依赖弱随机数或要求用户额外配置 HTTPS。

同时发现车载会话桥仍为旧运行进程：health 正常、无 active/fault/queue，但 `/v1/presentation` 返回404。确认没有执行中的请求后，通过既有 `XLeRobot-Onboard` 任务重启到已同步代码，回执接口恢复，持久会话身份未变，`motion_enabled=false`。未删除消息、重置会话或重放旧任务。

真实验收在局域网 HTTP 页面点击一次发送，消息明确要求只回复“消息链路正常”、不调用工具或控制机器人；网页收到真实车载智能回复，输入框清空、发送按钮恢复。回执保存在本地，测试不是只验证一个模拟HTTP返回。

## 吊顶与关节实现

原 Jom 模型按材质划为4网格，整个机械臂是一个静态网格，没有可用的关节层级。`presentation.rig_moss` 对机械臂进行位置焊接后的连通分件分析，将52个完整连通分件分配到固定座、上臂、竖轴、下臂；不切断三角面，不修改原位置、UV、法线或贴图。

增加顶端回转、上端转轴、下端转轴和本体俯仰节点。机身请求朝向分配到三个竖直轴，最后在本体横轴做俯仰；顶座不参与姿态动画。连杆跟随父节点，接口位置与杆长保持连接。转轴由模型几何外观推定，属于展示用约束，不是物理尺寸标定、完整逆运动学或实体机器人控制。

`MossRig` 限制本体偏航到±0.55rad、俯仰±0.20rad。主展示以指针位置及轻微待机/工作反馈驱动关节，不再修改整组根节点的旋转或上下漂浮。固定安装板在视口顶部，按当前相机视场调整取景，使左右分栏、过程收起居中、缩放与窄屏时仍贴住顶部。悬挂版不使用原地板投影；装饰参考线不再拦截指针事件。

检视页将“观察方位/俯仰”和“机身转向/俯仰”分开：前者用于绕模型检查，后者仅驱动关节，顶座固定。导出 GLB 带关节层级与署名，默认导出静止姿态；展示页的实时驱动代码不烘焙进动画。
