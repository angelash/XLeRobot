# Studio 存储空间监测

入口为原 Studio 的 `/#storage`，页面 `/storage/view` 和接口 `/api/platform/storage/*` 由原 8770 进程承载。主导航、能力目录和所有页面的顶部状态均可进入。无需新增端口、开机任务或依赖，不连接串口，也不自动清理资料。

## 检测与预警

- 每60秒读取所有本地固定卷的容量。Windows使用本机卷枚举及磁盘容量API，拔除或无法读取的卷标为未知。
- 任一条件触发提醒：剩余不超过20GiB，或剩余比例不超过15%。紧急提醒：不超过5GiB，或不超过5%。恢复到阈值以上自动解除。GiB按1024³字节计。
- 全站顶部每30秒读取独立的空间摘要，容量采样超过3分钟即标过期。控制服务离线不阻断空间检查。后台在Studio运行时持续检查；Studio停止或笔记本休眠期间不检查。
- 最近1440份容量记录保留在平台私有数据目录 `storage/snapshot.json`。页面按实际时间显示最近120次采样变化。此机制不替代SSD健康诊断，不预测精确写满时间。

## 资料统计

每15分钟在独立线程扫描文件元数据；容量检测使用另一线程，不等待目录扫描。每次最多60秒、500000文件。手动重新统计合并为一个待执行请求，不在HTTP请求中递归扫描。达到上限、读取失败或目录不存在均明确标为部分统计；保留上次结果、扫描时间和错误。

默认统计工程、实际平台数据、地图与FieldTests；当工程位于 `Robot` 目录内时覆盖该目录及已有同级 `RobotTransfer`、`RobotTools`。自动合并父子范围，避免重复计数，不接受网页传入路径。地图与FieldTests沿用现有私有配置。工作端和车载机器的结果彼此独立，页面明确显示采集主机。物理磁盘型号、总量、总线、分区及Windows健康报告由目录线程读取，不阻塞容量检查。

图片数量包含现场照片、截图及项目插图，不以扩展名推断拍摄者或内容。按用途的分类互斥：运行依赖、部署恢复资料、实物测试证据、地图、Studio运行资料、工程其他；同时提供独立的文件类型统计、各根目录的一级目录汇总与最大20个文件。用途分类以路径为依据，不代表文件可删除。

统计只读取文件元数据，跳过符号链接和Windows reparse point，不读取图片/文档内容。总量是动态文件系统中每个文件名的逻辑长度之和，硬链接按名称计数，不等于簇分配量；不能据目录合计解释整个磁盘的系统文件、权限遗漏或扫描范围以外占用。页面列出的前40个一级目录只用于展示，不改变总量。

## 接口与验证

- `GET /api/platform/storage/summary`：缓存的容量、预警、时间及采集主机。
- `GET /api/platform/storage/status`：摘要、规则、目录统计、范围、错误及最近容量记录。
- `POST /api/platform/storage/refresh`：仅接受空JSON对象，检查现有Studio来源规则，安排后台扫描。

聚焦检查：`python -m pytest deployment/storage -q`，`node --test deployment/storage/test_page.cjs`，并运行既有平台接口与页面回归。真实部署核对源文件哈希、原控制PID、数据/地图数量与真实页面；生成数据模拟预警与读取失败，不通过填满真实硬盘测试。
